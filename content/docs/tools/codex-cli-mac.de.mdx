Nach der Installation der Codex CLI legst du eine einzige Konfigurationsdatei manuell an, die `config.toml` (der Key kommt darin in einen Request-Header), um die Verbindung zur LMU AI API herzustellen – ein Konfigurationstool von Drittanbietern ist nicht nötig.

---

## Schritt 1 – Node.js installieren

Du brauchst **Node.js 20+** – Download: [https://nodejs.org/en/download](https://nodejs.org/en/download)

Klicke dich durch den Installer und prüfe danach im Terminal:

```bash
node --version
# A version number (e.g. v23.7.0) means it installed correctly
```

## Schritt 2 – Codex CLI installieren

```bash
npm i -g @openai/codex
```

Bei Netzwerkproblemen wechsle zuerst auf einen China-Mirror:

```bash
npm config set registry https://registry.npmmirror.com
npm i -g @openai/codex
```

Installation prüfen:

```bash
codex --version
# A version number means it installed correctly
```

## Schritt 3 – Konfigurationsdateien anlegen

Das Konfigurationsverzeichnis ist **`~/.codex/`** (bei Bedarf anlegen; alte Dateien überschreiben). Lege darin die `config.toml` an bzw. überschreibe sie:

### config.toml

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

<Callout type="warn" title="Der Key kommt in einen Request-Header">

- Ersetze in der letzten Zeile „your sk- key generated in the console“ (deinen in der Konsole erzeugten Key) durch deinen `sk-` Key und **lasse zwischen `Bearer` und dem Key genau ein Leerzeichen**, z. B. `Authorization = "Bearer sk-xxxx"`
- Setze den Abschnitt `[model_providers.codex.http_headers]` ans **Ende** der Datei, danach dürfen keine weiteren Einstellungen folgen
- Neuere Codex-Versionen brauchen keine `auth.json` mehr. Wenn du nach der alten Anleitung eine erstellt hast, schadet es nicht, sie liegen zu lassen – du kannst sie auch löschen (behalte sie, wenn du die [Bildgenerierungs-Skill der Codex App](/de/docs/tools/codex-api-image) nutzt)
- Falls in deiner alten Konfiguration im Abschnitt `[model_providers.codex]` die Zeile `requires_openai_auth = true` steht, lösche einfach diese Zeile

</Callout>

## Schritt 4 – Codex CLI starten

Öffne nach dem Speichern der Konfigurationsdateien das Terminal neu und führe Folgendes aus, um Codex zu starten und automatisch anzumelden:

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

Oder in der Kurzform:

```bash
codex --yolo
```

> Dieser Startbefehl überspringt Sicherheitsbestätigungen, du musst also nicht jeden automatisch ausgeführten Schritt freigeben.

Bei erfolgreichem Start zeigt die Oberfläche das aktuelle Modell als `gpt-5.4 xhigh` an (das Modell, das über das Feld `model` in der `config.toml` gesetzt ist).

<Callout type="info" title="Zum Modellwechsel">

Wenn du in einer Sitzung versehentlich auf ein anderes Modell wechselst, setze das Feld `model` in `~/.codex/config.toml` zurück auf `gpt-5.4` und starte das Terminal neu, um den Zustand wiederherzustellen.

</Callout>

## 1M-Kontext in Codex aktivieren (optional)

`gpt-5.4` unterstützt ein **1M-Token-Langkontextfenster** (standardmäßig 272K), nützlich für Reviews großer Repositories, die Analyse langer Logs und dateiübergreifende Refactorings. Codex aktiviert das 1M-Fenster **nicht** standardmäßig; du musst es ausdrücklich in der `config.toml` deklarieren.

### Konfiguration: zwei Zeilen in der config.toml ergänzen

Bearbeite `~/.codex/config.toml` und ergänze Folgendes auf der **obersten Ebene** (vor jedem `[Abschnitt]`, z. B. direkt nach `model = "gpt-5.4"`):

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Speichern, Terminal neu öffnen und Codex erneut starten, damit die Änderung greift.

**Feldübersicht**

| Feld | Zweck |
|------|------|
| `model_context_window` | Deklariert das nutzbare Kontextfenster des Modells in Token; `1000000` entspricht 1M. Ohne Angabe gilt der Modellstandard (272K) |
| `model_auto_compact_token_limit` | Der Token-Schwellwert, der die automatische Komprimierung des Verlaufs auslöst; setze ihn auf etwa 90 % des Fensters (`900000` bei 1M). Werte über 90 % des Fensters werden von Codex begrenzt, ein höherer Wert ist daher sinnlos |

### Prüfen, ob es greift

Gib nach dem Neustart von Codex `/status` ein und prüfe, ob `context window` rund 1M anzeigt (manche Versionen zeigen etwa 950K – ein von Codex reservierter Sicherheitsabstand von 5 %). Mit `/statusline` kannst du die Kontextnutzung außerdem in die Statusleiste einblenden und live mitverfolgen.

### Wenn du CC Switch nutzt

Wenn du die Codex-Konfiguration mit [CC Switch](/de/docs/tools/cc-switch) verwaltest, ergänze die beiden Zeilen im dortigen Codex-Konfigurationseditor und übernimm sie – die Wirkung ist identisch:

![Setzen von model_context_window = 1000000 und model_auto_compact_token_limit = 900000 für die Codex-Konfiguration in CC Switch, um den 1M-Token-Langkontext zu aktivieren](/images/tools/codex/codex-ccs.png)

<Callout type="warn" title="Hinweise zur Nutzung">

- **Muss auf der obersten Ebene stehen**: Innerhalb eines Abschnitts `[profiles.xxx]` greifen diese beiden Felder nicht (eine bekannte Einschränkung von Codex); setze sie außerdem in die benutzerweite `~/.codex/config.toml`, da eine projektbezogene `.codex/config.toml` möglicherweise ignoriert wird
- **Modellunterstützung**: `gpt-5.4` und `gpt-5.5` unterstützen 1M über den API-Kanal; Modelle wie `gpt-5.3-codex` sind auf 272K begrenzt, und kein Konfigurationswert kann das Limit des Modells selbst überschreiten
- **Höhere Kosten**: Ein längerer Kontext verbraucht pro Anfrage mehr Token; der Anteil oberhalb von 272K wird zum höheren Langkontext-Tarif abgerechnet – lass die Einstellung also nur für sehr lange Aufgaben aktiv
- **Versionsunterschiede**: Manche neueren Codex-Versionen lesen die Fenstergröße zuerst aus dem Modellkatalog; zeigt `/status` weiterhin den alten Wert, aktualisiere auf die neueste Version (`npm i -g @openai/codex@latest`) und versuche es erneut

</Callout>
