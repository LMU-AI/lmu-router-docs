Codex CLI をインストールしたあと、設定ファイル `config.toml` を 1 つ手動で作成するだけ（キーはその中のリクエストヘッダーに記述します）で LMU AI API に接続できます。サードパーティの設定ツールは不要です。

---

## ステップ 1 — Node.js をインストール

**Node.js 20+** が必要です。ダウンロード: [https://nodejs.org/en/download](https://nodejs.org/en/download)

インストーラーを進めたあと、ターミナルで確認します:

```bash
node --version
# A version number (e.g. v23.7.0) means it installed correctly
```

## ステップ 2 — Codex CLI をインストール

```bash
npm i -g @openai/codex
```

ネットワークの問題が出る場合は、先に中国のミラーに切り替えてください:

```bash
npm config set registry https://registry.npmmirror.com
npm i -g @openai/codex
```

インストールを確認します:

```bash
codex --version
# A version number means it installed correctly
```

## ステップ 3 — 設定ファイルを作成

設定ディレクトリは **`~/.codex/`** です（無ければ作成し、古いファイルは上書きしてください）。その中に `config.toml` を作成／上書きします:

### config.toml

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

<Callout type="warn" title="キーはリクエストヘッダーに記述します">

- 最後の行の「コンソールで発行した sk- キー」を自分の `sk-` キーに置き換えます。**`Bearer` とキーの間にはスペースを 1 つ入れてください**。例: `Authorization = "Bearer sk-xxxx"`
- `[model_providers.codex.http_headers]` セクションはファイルの**最後**に置き、その後に他の設定を書かないでください
- 新しいバージョンの Codex では `auth.json` は不要です。旧ガイドに従って作成済みの場合、そのまま残しても問題ありませんし、削除しても構いません（[Codex App の画像生成スキル](/ja/docs/tools/codex-api-image)を使う場合は残してください）
- 古い設定の `[model_providers.codex]` セクションに `requires_openai_auth = true` がある場合は、その行を削除するだけで済みます

</Callout>

## ステップ 4 — Codex CLI を起動

設定ファイルを保存したら、ターミナルを開き直して以下を実行すると、自動的に起動・サインインします:

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

または短縮形:

```bash
codex --yolo
```

> この起動コマンドはセキュリティ承認をスキップするため、自動実行される各ステップを承認する必要がなくなります。

正常に起動すると、画面に現在のモデルとして `gpt-5.4 xhigh` が表示されます（`config.toml` の `model` フィールドで設定したモデルです）。

<Callout type="info" title="モデル切り替えについて">

セッション中に誤って別のモデルに切り替えてしまった場合は、`~/.codex/config.toml` の `model` フィールドを `gpt-5.4` に戻し、ターミナルを再起動すれば元に戻ります。

</Callout>

## Codex で 1M コンテキストを有効にする（任意）

`gpt-5.4` は **1M トークンのロングコンテキストウィンドウ**に対応しています（デフォルトは 272K）。大規模リポジトリのレビュー、長いログの解析、ファイル横断のリファクタリングに便利です。Codex はデフォルトでは 1M ウィンドウを有効にしないため、`config.toml` で明示的に宣言する必要があります。

### 設定方法: config.toml に 2 行追加する

`~/.codex/config.toml` を編集し、**トップレベル**（どの `[section]` よりも前、例えば `model = "gpt-5.4"` の直後）に以下を追加します:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

保存してターミナルを開き直し、Codex に再入室すると適用されます。

**フィールドの説明**

| フィールド | 用途 |
|------|------|
| `model_context_window` | モデルが使用可能なコンテキストウィンドウをトークン単位で宣言します。`1000000` は 1M です。未設定の場合はモデルのデフォルト（272K）が使われます |
| `model_auto_compact_token_limit` | 履歴の自動圧縮がトリガーされるトークン閾値。ウィンドウの約 90%（1M なら `900000`）に設定します。ウィンドウの 90% を超える値は Codex 側で丸められるため、それ以上大きくしても意味がありません |

### 適用されたか確認する

Codex に再入室したあと `/status` と入力し、`context window` が 1M 前後になっているか確認してください（一部バージョンでは約 950K と表示されます。Codex が 5% の安全マージンを予約しているためです）。`/statusline` を使ってコンテキスト使用量をステータスバーに表示し、リアルタイムで監視することもできます。

### CC Switch を使っている場合

[CC Switch](/ja/docs/tools/cc-switch) で Codex の設定を管理している場合は、その Codex 設定エディターに同じ 2 行を追加して適用してください。効果は同じです:

![CC Switch の Codex 設定で model_context_window = 1000000 と model_auto_compact_token_limit = 900000 を設定し、1M トークンのロングコンテキストを有効にする](/images/tools/codex/codex-ccs.png)

<Callout type="warn" title="利用上の注意">

- **トップレベルに置く必要があります**: この 2 つのフィールドは `[profiles.xxx]` セクション内では有効になりません（Codex の既知の制限）。また、プロジェクトレベルの `.codex/config.toml` は無視される場合があるため、ユーザーレベルの `~/.codex/config.toml` に記述してください
- **モデル対応状況**: API チャネルでは `gpt-5.4` と `gpt-5.5` が 1M に対応しています。`gpt-5.3-codex` などは 272K が上限で、設定値がモデル自体の上限を超えることはできません
- **コスト増**: コンテキストが長くなるとリクエストあたりのトークン消費が増えます。272K を超えた部分はより高いロングコンテキスト料金で課金されるため、本当に長いタスク以外では有効にしたままにしないでください
- **バージョン差異**: 一部の新しいバージョンの Codex はモデルカタログからウィンドウサイズを優先的に読み取ります。`/status` が古い値のままの場合は、最新版にアップグレード（`npm i -g @openai/codex@latest`）して再試行してください

</Callout>
