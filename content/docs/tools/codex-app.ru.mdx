Если вы не хотите устанавливать Codex CLI и хотите просто пользоваться **десктопным клиентом Codex App**, воспользуйтесь этим способом.

<Callout type="warn" title="Примечание">

- Если ранее вы входили под своим аккаунтом, сначала **выйдите из текущего аккаунта** в Codex App, а затем выполните настройку заново.
- После переключения на API ваша история переписки исчезнет (история при входе по аккаунту хранится в пространстве вашего аккаунта GPT, а не локально).
- **После перехода на вход по API вся последующая история переписки сохраняется локально и не потеряется!**

</Callout>

## Шаг 1 — Создайте файлы конфигурации

Расположение файла конфигурации:
- **Mac/Linux**: папка `.codex` в домашнем каталоге (`~`)
- **Windows**: `C:\users\your-username\.codex\`

Если папка уже существует, лучше удалить находящийся в ней `config.toml` (а также `auth.json`, оставшийся от прежней инструкции) и создать заново, чтобы старая конфигурация не мешала.

**Создание папки командой в терминале:**

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

Создайте `config.toml` в папке `.codex`.

### config.toml

Настройте поставщика услуг; ключ API указывается в заголовке запроса в самом конце файла:

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

Замените последнюю строку своим ключом `sk-`, сохранив один пробел между `Bearer` и ключом. Разместите секцию `[model_providers.codex.http_headers]` в самом конце файла, чтобы после неё не было других настроек.

<Callout type="info">

Обычно он находится в папке `.codex` в вашем домашнем каталоге. Если папки `.codex` там нет, вы можете создать её вручную, а затем создать в ней `config.toml`.

Содержимое файла конфигурации полностью совпадает с [инструкцией по настройке Codex CLI для Mac/Linux](/ru/docs/tools/codex-cli-mac) — вы можете создать файлы по этой инструкции в терминале, и они точно так же вступят в силу после перезапуска Codex App.

</Callout>

## Шаг 2 — Перезапустите Codex App

После сохранения файлов конфигурации снова откройте Codex App — вход выполнится автоматически, и приложение будет готово к работе.

---

## Включение контекста на 1M (необязательно)

`gpt-5.4` поддерживает длинный контекст на 1M токенов, но по умолчанию он отключён. Добавьте две строки на **верхнем уровне** приведённого выше `config.toml` (до любой секции `[section]`), затем перезапустите Codex App:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

О значении полей, способах проверки и нюансах см. [Включение контекста на 1M в Codex](/ru/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).

## Типичные ошибки

**Ошибка 401, неверный ключ:**

Причина: запрос по-прежнему идёт на официальный эндпоинт OpenAI, а не на наш релей API, либо вы не перезапустили инструмент для перезагрузки файла конфигурации.

Решение: ещё раз пройдите инструкцию, создав или заменив `config.toml`, затем снова откройте приложение.

**Ошибка 401 API_KEY_REQUIRED:**

Причина: новые версии Codex могут больше не читать ключ из `auth.json`, поэтому запрос отправляется без ключа.

Решение: добавьте секцию `[model_providers.codex.http_headers]` в конец `config.toml`, как показано выше; см. [FAQ · Issue 10](/ru/docs/guide/faq#issue-10).
