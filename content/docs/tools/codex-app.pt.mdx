Se você não quer instalar o Codex CLI e só quer usar o **cliente desktop Codex App**, siga este método.

<Callout type="warn" title="Observação">

- Se você já entrou antes com sua própria conta, primeiro **saia da conta atual** no Codex App e depois reconfigure.
- Depois de trocar a API, seu histórico de conversas desaparece (o histórico do tipo conta fica armazenado no espaço da sua conta GPT, não localmente).
- **Depois que você mudar para o login por API, todo o histórico de conversas a partir daí é salvo localmente e não será perdido!**

</Callout>

---

## Passo 1 — Criar os arquivos de configuração

Local dos arquivos de configuração:
- **Mac/Linux**: a pasta `.codex` no seu diretório pessoal (`~`)
- **Windows**: `C:\users\seu-usuario\.codex\`

Se a pasta já existir, o ideal é apagar o `config.toml` que está dentro dela (e qualquer `auth.json` que tenha sobrado do guia antigo) e recriá-lo, para evitar interferência de configurações antigas.

**Crie a pasta com um comando no terminal:**

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

Crie o `config.toml` na pasta `.codex`.

### config.toml

Configure o provedor de serviço; a chave de API vai em um cabeçalho de requisição no final do arquivo:

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

Substitua a última linha pela sua chave `sk-`, mantendo um espaço entre `Bearer` e a chave. Coloque a seção `[model_providers.codex.http_headers]` no final do arquivo, sem nenhuma outra configuração depois dela.

<Callout type="info">

Normalmente fica dentro da pasta `.codex` no seu diretório pessoal. Se você não encontrar a pasta `.codex` lá, pode criá-la manualmente e depois criar o `config.toml` dentro dela.

O conteúdo dos arquivos de configuração é idêntico ao do [guia de configuração do Codex CLI no Mac/Linux](/pt/docs/tools/codex-cli-mac) — você pode seguir aquele guia para criá-los no terminal, e eles passam a valer depois de reiniciar o Codex App do mesmo jeito.

</Callout>

## Passo 2 — Reabrir o Codex App

Depois de salvar os arquivos de configuração, reabra o Codex App: ele fará login e estará pronto para uso automaticamente.

---

## Ativando o contexto de 1M (opcional)

O `gpt-5.4` suporta um contexto longo de 1M tokens, mas ele vem desativado por padrão. Adicione duas linhas no **nível raiz** do `config.toml` acima (antes de qualquer `[section]`) e depois reinicie o Codex App:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Para o significado dos campos, como verificar e as ressalvas, veja [Ativando o contexto de 1M no Codex](/pt/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).

## Erros comuns

**Erro 401, chave incorreta:**

Causa: a requisição continua indo para o endpoint oficial da OpenAI em vez do nosso relay de API, ou você não reiniciou a ferramenta para recarregar o arquivo de configuração.

Solução: siga o guia novamente para criar ou substituir o `config.toml` e depois reabra o aplicativo.

**Erro 401 API_KEY_REQUIRED:**

Causa: versões mais novas do Codex podem não ler mais a chave do `auth.json`, então a requisição vai sem chave.

Solução: adicione a seção `[model_providers.codex.http_headers]` no final do `config.toml` como mostrado acima; veja [FAQ · Problema 10](/pt/docs/guide/faq#issue-10).
