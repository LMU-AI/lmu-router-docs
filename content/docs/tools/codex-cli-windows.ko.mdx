Codex CLI를 설치한 뒤 설정 파일 `config.toml` 하나만 직접 만들면(키는 그 안의 요청 헤더에 들어갑니다) LMU AI API에 연결할 수 있습니다 — 서드파티 설정 도구는 필요 없습니다.

---

## 1단계 — Windows Terminal 설치

Windows에서는 Codex CLI를 쓸 때 CMD 대신 **Windows Terminal** 사용을 권장합니다 — 여러 창을 지원해서 더 편리합니다.

- 중국 클라우드 드라이브 다운로드(권장, 빠름): [https://www.ilanzou.com/s/MzWnpE05](https://www.ilanzou.com/s/MzWnpE05)
- GitHub 다운로드: [https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0](https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0)

`Microsoft.WindowsTerminal_1.23.20211.0_x64.zip`을 다운로드해 압축을 풀고 `WindowsTerminal.exe`를 더블클릭해 실행하세요 — 바탕화면에 바로 가기를 만들어 두면 좋습니다.

## 2단계 — Node.js 설치

> 이미 설치되어 있다면 건너뛰어도 됩니다. 확인 방법: `node -v`

**Node.js 20+** 가 필요합니다 — 다운로드: [https://nodejs.org/en/download](https://nodejs.org/en/download)

설치 과정에서 **"Automatically install the necessary tools"** 항목을 반드시 체크하세요.

설치 후 터미널에서 확인합니다:

```bash
node -v
# A version number (e.g. v24.4.1) means it installed correctly
```

<Callout type="info" title="특수한 경우">

`node.js`가 설치되어 있지 않거나, 이전에 설치했지만 환경 설정이 잘못된 경우에는 다시 다운로드해 한 번 재설치한 뒤 터미널을 새로 열어 주세요.

</Callout>

**스크립트 실행 차단 오류가 발생하면 다음 명령을 실행하세요:**

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## 3단계 — Codex CLI 설치

```bash
npm i -g @openai/codex
```

네트워크 문제가 발생하면 먼저 중국 미러로 전환한 뒤 설치하세요:

```bash
npm config set registry https://registry.npmmirror.com
npm i -g @openai/codex
```

설치 확인:

```bash
codex --version
# A version number means it installed correctly
```

## 4단계 — 설정 파일 만들기

설정 디렉터리는 **`C:\users\your-username\.codex\`** 입니다(없으면 생성하고, 오래된 파일은 덮어쓰세요). 이 디렉터리에 `config.toml`을 생성/덮어쓰기 합니다:

### config.toml

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

<Callout type="warn" title="키는 요청 헤더에 들어갑니다">

- 마지막 줄의 "콘솔에서 생성한 sk- 키"를 본인의 `sk-` 키로 바꾸고, **`Bearer`와 키 사이에 공백 한 칸을 유지**하세요. 예: `Authorization = "Bearer sk-xxxx"`
- `[model_providers.codex.http_headers]` 섹션은 파일의 **맨 마지막**에 두고, 그 뒤에 다른 설정을 넣지 마세요
- 최신 Codex 버전에서는 `auth.json`이 더 이상 필요하지 않습니다. 예전 가이드대로 만들어 두었다면 그대로 둬도 무해하며, 삭제해도 됩니다([Codex App 이미지 생성 스킬](/ko/docs/tools/codex-api-image)을 사용한다면 그대로 두세요)
- 기존 설정의 `[model_providers.codex]` 섹션에 `requires_openai_auth = true`가 있다면 그 줄만 삭제하세요

</Callout>

## 5단계 — Codex CLI 실행

설정 파일을 저장한 뒤 터미널을 새로 열고 다음을 실행하면 자동으로 실행 및 로그인됩니다:

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

또는 짧은 형태:

```bash
codex --yolo
```

> 이 실행 명령은 보안 승인 절차를 건너뛰므로, 자동 실행되는 각 단계를 매번 승인하지 않아도 됩니다.

정상적으로 실행되면 인터페이스에 현재 모델이 `gpt-5.4 xhigh`로 표시됩니다(`config.toml`의 `model` 필드에서 설정한 모델입니다).

## Codex에서 1M 컨텍스트 활성화하기 (선택)

`gpt-5.4`는 **1M 토큰 롱 컨텍스트 윈도우**를 지원합니다(기본값은 272K에 불과). 매우 큰 저장소 리뷰, 긴 로그 분석, 여러 파일에 걸친 리팩터링 같은 작업에 유용합니다. Codex는 1M 윈도우를 기본으로 활성화하지 **않으므로**, `config.toml`에 명시적으로 선언해야 합니다.

### 설정 방법: config.toml에 두 줄 추가

`C:\users\your-username\.codex\config.toml`을 편집해 **최상위 레벨**에(모든 `[section]`보다 앞, 예를 들어 `model = "gpt-5.4"` 바로 다음에) 다음을 추가하세요:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

저장한 뒤 터미널을 새로 열고 Codex에 다시 들어가면 적용됩니다.

**필드 설명**

| 필드 | 용도 |
|------|------|
| `model_context_window` | 모델이 사용할 수 있는 컨텍스트 윈도우를 토큰 단위로 선언합니다. `1000000`은 1M입니다. 설정하지 않으면 모델 기본값(272K)을 사용합니다 |
| `model_auto_compact_token_limit` | 히스토리 자동 압축(auto-compact)을 트리거하는 토큰 임계값입니다. 윈도우의 약 90%로 설정하세요(1M이면 `900000`). 윈도우의 90%를 넘는 값은 Codex가 제한하므로 더 큰 숫자를 넣어도 의미가 없습니다 |

### 적용 여부 확인

Codex에 다시 들어간 뒤 `/status`를 입력해 `context window`가 1M 정도로 표시되는지 확인하세요(일부 버전에서는 약 950K로 표시되는데, Codex가 5%를 안전 여유로 남겨둔 것입니다). `/statusline`을 사용해 상태 바에 컨텍스트 사용량을 추가하고 실시간으로 모니터링할 수도 있습니다.

### CC Switch를 사용하는 경우

[CC Switch](/ko/docs/tools/cc-switch)로 Codex 설정을 관리한다면, 해당 도구의 Codex 설정 편집기에서 동일한 두 줄을 추가하고 적용하면 됩니다 — 효과는 같습니다:

![CC Switch의 Codex 설정에서 model_context_window = 1000000 및 model_auto_compact_token_limit = 900000을 설정해 1M 토큰 롱 컨텍스트를 활성화하는 화면](/images/tools/codex/codex-ccs.png)

<Callout type="warn" title="사용 시 주의사항">

- **반드시 최상위 레벨에 둘 것**: 이 두 필드는 `[profiles.xxx]` 섹션 안에서는 적용되지 않습니다(알려진 Codex 제한). 또한 프로젝트 단위의 `.codex\config.toml`은 무시될 수 있으므로 사용자 단위인 `C:\users\your-username\.codex\config.toml`에 넣으세요
- **모델 지원**: `gpt-5.4`와 `gpt-5.5`는 API 채널에서 1M을 지원합니다. `gpt-5.3-codex` 같은 모델은 272K로 제한되며, 어떤 설정값도 모델 자체의 상한을 넘을 수 없습니다
- **비용 증가**: 컨텍스트가 길어질수록 요청마다 사용하는 토큰이 늘어납니다. 272K를 초과하는 부분은 더 높은 롱 컨텍스트 요율로 과금되므로, 아주 긴 작업이 아니면 켜둔 채로 두지 마세요
- **버전 차이**: 일부 최신 Codex 버전은 윈도우 크기를 모델 카탈로그에서 먼저 읽어옵니다. `/status`에 여전히 이전 값이 표시되면 최신 버전으로 업그레이드(`npm i -g @openai/codex@latest`)한 뒤 다시 시도하세요

</Callout>
