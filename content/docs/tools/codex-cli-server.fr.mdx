Pour configurer le Codex CLI dans un environnement WSL2 ou sur un serveur distant en SSH.

---

## Étapes de configuration

### Étape 1 — Installer l'environnement Node.js (avec volta)

Dans le terminal du serveur, exécutez :

```bash
curl https://get.volta.sh | bash
```

### Étape 2 — Installer Node 20

<Callout type="warn" title="Remarque">

Une fois volta installé avec succès, vous **devez ouvrir une nouvelle fenêtre de terminal** avant d'exécuter la commande suivante :

</Callout>

```bash
volta install node@20
```

### Étape 3 — Installer le Codex CLI

```bash
volta install @openai/codex
```

### Étape 4 — Créer les fichiers de configuration

Exécutez ce qui suit dans le terminal du serveur pour écrire `~/.codex/config.toml` en une seule fois (**n'oubliez pas de remplacer « votre clé sk- générée dans la console » sur la dernière ligne par votre clé `sk-`, en conservant un espace après `Bearer`**) :

```bash
mkdir -p ~/.codex

cat > ~/.codex/config.toml <<'EOF'
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
EOF
```

Le contenu de la configuration est identique à celui du [guide Codex CLI (Mac/Linux)](/fr/docs/tools/codex-cli-mac) — vous pouvez aussi le créer à la main avec `vim` / `nano`. Les versions récentes de Codex n'ont plus besoin de `~/.codex/auth.json` ; en laisser un ancien en place est sans conséquence.

### Étape 5 — Lancer le Codex CLI

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

Ou :

```bash
codex --yolo
```

## Activer le contexte de 1M (optionnel)

`gpt-5.4` prend en charge un contexte long de 1M tokens, mais il est désactivé par défaut. Modifiez `~/.codex/config.toml`, ajoutez deux lignes au **niveau racine** du fichier (avant toute `[section]`), puis relancez Codex :

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Pour la signification des champs, la méthode de vérification et les points d'attention, voir [Activer le contexte de 1M dans Codex](/fr/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).
