Für die Konfiguration der Codex CLI in einer WSL2- oder SSH-Remote-Server-Umgebung.

---

## Konfigurationsschritte

### Schritt 1 — Node.js-Umgebung installieren (mit volta)

Führe im Terminal des Servers aus:

```bash
curl https://get.volta.sh | bash
```

### Schritt 2 — Node 20 installieren

<Callout type="warn" title="Hinweis">

Nachdem volta erfolgreich installiert wurde, **musst du ein neues Terminalfenster öffnen**, bevor du den folgenden Befehl ausführst:

</Callout>

```bash
volta install node@20
```

### Schritt 3 — Codex CLI installieren

```bash
volta install @openai/codex
```

### Schritt 4 — Konfigurationsdateien erstellen

Führe Folgendes im Terminal des Servers aus, um `~/.codex/config.toml` in einem Durchgang zu schreiben (**denke daran, „dein in der Konsole generierter sk- Key" in der letzten Zeile durch deinen `sk-`-Key zu ersetzen, und behalte dabei das eine Leerzeichen nach `Bearer`**):

```bash
mkdir -p ~/.codex

cat > ~/.codex/config.toml <<'EOF'
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
EOF
```

Die Konfigurationsinhalte sind identisch mit der [Anleitung Codex CLI (Mac/Linux)](/de/docs/tools/codex-cli-mac) — du kannst die Datei auch manuell mit `vim` / `nano` erstellen. Neuere Codex-Versionen benötigen `~/.codex/auth.json` nicht mehr; eine alte Datei, die noch vorhanden ist, richtet keinen Schaden an.

### Schritt 5 — Codex CLI starten

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

Oder:

```bash
codex --yolo
```

## 1M-Kontext aktivieren (optional)

`gpt-5.4` unterstützt einen langen Kontext von 1M Token, der standardmäßig jedoch deaktiviert ist. Bearbeite `~/.codex/config.toml`, füge zwei Zeilen auf der **obersten Ebene** der Datei hinzu (vor jeder `[section]`) und starte Codex neu:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Zur Bedeutung der Felder, zur Überprüfung und zu den Einschränkungen siehe [1M-Kontext in Codex aktivieren](/de/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).
