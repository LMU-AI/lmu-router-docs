بعد تثبيت Codex CLI، أنشئ ملف إعداد واحد يدويًا، وهو `config.toml` (يُوضع المفتاح داخله في ترويسة طلب)، للاتصال بواجهة LMU AI API — دون الحاجة إلى أي أداة إعداد من جهة خارجية.

---

## الخطوة 1 — تثبيت Windows Terminal

على Windows، نوصي باستخدام **Windows Terminal** بدلًا من CMD مع Codex CLI — فهو يدعم نوافذ متعددة وأكثر راحة في الاستخدام.

- التحميل من التخزين السحابي في الصين (موصى به، سريع): [https://www.ilanzou.com/s/MzWnpE05](https://www.ilanzou.com/s/MzWnpE05)
- التحميل من GitHub: [https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0](https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0)

نزّل الملف `Microsoft.WindowsTerminal_1.23.20211.0_x64.zip`، وفك ضغطه، وانقر نقرًا مزدوجًا على `WindowsTerminal.exe` للتشغيل — ومن الجيد إنشاء اختصار على سطح المكتب.

## الخطوة 2 — تثبيت Node.js

> إذا كان مثبتًا بالفعل يمكنك تخطي هذه الخطوة؛ تحقق بالأمر: `node -v`

تحتاج إلى **Node.js 20+** — التحميل: [https://nodejs.org/en/download](https://nodejs.org/en/download)

أثناء التثبيت، تأكد من تحديد خيار **"Automatically install the necessary tools"**.

بعد التثبيت، تحقق في الطرفية:

```bash
node -v
# A version number (e.g. v24.4.1) means it installed correctly
```

<Callout type="info" title="حالة خاصة">

إذا لم يكن `node.js` مثبتًا، أو كنت قد ثبّته سابقًا لكن البيئة غير مهيأة بشكل صحيح، فنزّله وأعد تثبيته مرة واحدة، ثم أعد فتح الطرفية.

</Callout>

**إذا واجهت خطأ حجب تنفيذ السكربتات، نفّذ الأمر التالي:**

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## الخطوة 3 — تثبيت Codex CLI

```bash
npm i -g @openai/codex
```

إذا واجهت مشكلات في الشبكة، فانتقل أولًا إلى مرآة صينية، ثم ثبّت:

```bash
npm config set registry https://registry.npmmirror.com
npm i -g @openai/codex
```

تحقق من التثبيت:

```bash
codex --version
# A version number means it installed correctly
```

## الخطوة 4 — إنشاء ملفات الإعداد

مجلد الإعداد هو **`C:\users\your-username\.codex\`** (أنشئه إن لم يكن موجودًا؛ واستبدل أي ملفات قديمة). أنشئ/استبدل ملف `config.toml` داخله:

### config.toml

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

<Callout type="warn" title="يُوضع المفتاح في ترويسة طلب">

- استبدل "your sk- key generated in the console" في السطر الأخير بمفتاح `sk-` الخاص بك، **مع الإبقاء على مسافة واحدة بين `Bearer` والمفتاح**، مثال: `Authorization = "Bearer sk-xxxx"`
- ضع القسم `[model_providers.codex.http_headers]` في **نهاية** الملف تمامًا، دون أي إعدادات أخرى بعده
- إصدارات Codex الأحدث لم تعد تحتاج إلى `auth.json`. إذا أنشأته وفق الدليل القديم، فلا ضرر من تركه كما هو، أو يمكنك حذفه (أبقِه إن كنت تستخدم [مهارة توليد الصور في تطبيق Codex](/ar/docs/tools/codex-api-image))
- إذا كان إعدادك القديم يحتوي على `requires_openai_auth = true` داخل القسم `[model_providers.codex]`، فاحذف ذلك السطر فقط

</Callout>

## الخطوة 5 — تشغيل Codex CLI

بعد حفظ ملفات الإعداد، أعد فتح الطرفية ونفّذ ما يلي للتشغيل وتسجيل الدخول تلقائيًا:

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

أو الصيغة المختصرة:

```bash
codex --yolo
```

> أمر التشغيل هذا يتجاوز موافقات الأمان، فلن تحتاج إلى الموافقة على كل خطوة تُنفَّذ تلقائيًا.

عند التشغيل بنجاح، تُظهر الواجهة الموديل الحالي باسم `gpt-5.4 xhigh` (الموديل المحدد في الحقل `model` داخل `config.toml`).

## تمكين سياق 1M في Codex (اختياري)

يدعم `gpt-5.4` **نافذة سياق طويل بسعة مليون توكن** (272K فقط افتراضيًا)، وهي مفيدة لمراجعة المستودعات الضخمة جدًا، وتحليل السجلات الطويلة، وإعادة الهيكلة عبر ملفات متعددة، والمهام المشابهة. لا يُمكّن Codex نافذة 1M افتراضيًا؛ يجب أن تعلنها صراحةً في `config.toml`.

### طريقة الإعداد: أضف سطرين إلى config.toml

حرّر الملف `C:\users\your-username\.codex\config.toml` وأضف ما يلي في **المستوى الأعلى** (قبل أي `[section]`، مثلًا مباشرة بعد `model = "gpt-5.4"`):

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

احفظ الملف، وأعد فتح الطرفية، وادخل إلى Codex مرة أخرى لتطبيق التغيير.

**مرجع الحقول**

| الحقل | الوظيفة |
|------|------|
| `model_context_window` | يعلن نافذة السياق القابلة للاستخدام للموديل بوحدة التوكن؛ القيمة `1000000` تعني 1M. إن لم تُحدَّد، يُستخدم الإعداد الافتراضي للموديل (272K) |
| `model_auto_compact_token_limit` | حد التوكن الذي يفعّل الضغط التلقائي للمحادثات السابقة (auto-compact)؛ اضبطه على نحو 90% من النافذة (`900000` لنافذة 1M). القيم التي تتجاوز 90% من النافذة يقيّدها Codex، لذا لا جدوى من رقم أكبر |

### التحقق من سريان الإعداد

بعد الدخول إلى Codex مرة أخرى، اكتب `/status` وتحقق مما إذا كانت `context window` تظهر بنحو 1M (تُظهر بعض الإصدارات نحو 950K — وهو هامش أمان محفوظ بنسبة 5% من Codex). يمكنك أيضًا استخدام `/statusline` لإضافة استهلاك السياق إلى شريط الحالة لمراقبته مباشرة.

### إذا كنت تستخدم CC Switch

إذا كنت تدير إعداد Codex عبر [CC Switch](/ar/docs/tools/cc-switch)، فأضف السطرين نفسهما في محرر إعداد Codex الخاص به وطبّق التغيير — والنتيجة مماثلة تمامًا:

![ضبط model_context_window = 1000000 و model_auto_compact_token_limit = 900000 لإعداد Codex في CC Switch لتمكين السياق الطويل بسعة مليون توكن](/images/tools/codex/codex-ccs.png)

<Callout type="warn" title="ملاحظات الاستخدام">

- **يجب أن يكونا في المستوى الأعلى**: هذان الحقلان لا يسريان داخل قسم `[profiles.xxx]` (قيد معروف في Codex)؛ كما ينبغي وضعهما في ملف مستوى المستخدم `C:\users\your-username\.codex\config.toml`، لأن ملف `.codex\config.toml` على مستوى المشروع قد يُتجاهَل
- **دعم الموديلات**: يدعم `gpt-5.4` و `gpt-5.5` سعة 1M عبر قناة API؛ أما موديلات مثل `gpt-5.3-codex` فهي محدودة بـ 272K، ولا يمكن لأي قيمة في الإعداد أن تتجاوز حد الموديل نفسه
- **تكلفة أعلى**: كلما طال السياق، زاد عدد التوكنات المستهلكة في كل طلب؛ والجزء الذي يتجاوز 272K يُحاسب بشريحة السياق الطويل الأعلى سعرًا، فلا تُبقِه مفعّلًا إلا للمهام الطويلة جدًا
- **اختلافات الإصدارات**: بعض إصدارات Codex الأحدث تقرأ حجم النافذة من كتالوج الموديلات أولًا؛ إذا كان `/status` لا يزال يُظهر القيمة القديمة، فحدّث إلى أحدث إصدار (`npm i -g @openai/codex@latest`) وأعد المحاولة

</Callout>
