Crush ist ein Terminal-AI-Coding-Tool von [Charm](https://charm.land), das sowohl eine CLI als auch eine TUI für Codegenerierung, Debugging, Konversation, Dateioperationen und Multitasking über die Kommandozeile bietet. Es unterstützt benutzerdefinierte Provider — diese Seite behandelt die Verbindung mit LMU AI.

## LMU AI konfigurieren

Crush wird mit einem **Bash-Skript** konfiguriert. Bearbeite die globale Konfigurationsdatei:

- **macOS / Linux**: `~/.config/crush/crushrc`
- **Windows**: `%USERPROFILE%\.config\crush\crushrc`

Es gibt zwei Schritte: Füge LMU AI mit `provider add` als Provider hinzu und registriere dann die gewünschten Modelle mit `model add`. Wähle das Protokoll, das zu den Modellen passt, die du verwenden möchtest:

<Tabs items={['GPT / allgemein (openai-compat)', 'Claude / chinesische Modelle (anthropic)']}>
<Tab value="GPT / allgemein (openai-compat)">

Funktioniert für OpenAI-Modelle wie `gpt-5.6-sol` und `gpt-5.5`. Claude und chinesische Modelle können ebenfalls über dieses Protokoll laufen (das LMU-AI-Backend übernimmt die Protokollkonvertierung).

```bash
# Add LMU AI as a provider (OpenAI-compatible protocol)
provider add lmuai \
  --type openai-compat \
  --base-url "https://api.lmuai.com/v1" \
  --api-key "sk-your-lmu-ai-api-key"

# Register the models you want
model add lmuai/gpt-5.6-sol --name "GPT-5.6 Sol" --context-window 400000
model add lmuai/claude-opus-5 --name "Claude Opus 5" --context-window 200000

# Set it as the default large-model slot
model large lmuai/claude-opus-5
```

<Callout type="warn" title="Der Typ ist openai-compat, nicht openai">

Crush hat zwei OpenAI-Typen. Laut der offiziellen Dokumentation ist `openai` für das Proxying oder Routing von Anfragen **über OpenAI selbst** gedacht, während `openai-compat` für **Nicht-OpenAI-Provider mit OpenAI-kompatiblen APIs** ist. LMU AI ist Letzteres, also verwende `openai-compat`.

</Callout>

</Tab>
<Tab value="Claude / chinesische Modelle (anthropic)">

Funktioniert für Modelle, die über das Anthropic-Protokoll bereitgestellt werden, wie `claude-opus-5`, `claude-sonnet-5`, `qwen3.8-max-preview`, `deepseek-v4-pro`, `glm-5.2` und `kimi-k3`.

```bash
# Add LMU AI as a provider (Anthropic protocol)
provider add lmuai-anthropic \
  --type anthropic \
  --base-url "https://api.lmuai.com" \
  --api-key "sk-your-lmu-ai-api-key" \
  --extra-header anthropic-version 2023-06-01

# Register the models you want
model add lmuai-anthropic/claude-opus-5 \
  --name "Claude Opus 5" \
  --context-window 200000 \
  --can-reason true \
  --supports-images true

model add lmuai-anthropic/glm-5.2 --name "GLM-5.2" --context-window 200000

# Set it as the default large-model slot
model large lmuai-anthropic/claude-opus-5
```

<Callout type="warn" title="Füge dem Anthropic-Basis-URL kein /v1 hinzu">

Setze `--base-url` auf `https://api.lmuai.com` — **nicht** `https://api.lmuai.com/v1`. Crush hängt `/v1/messages` selbst an, sodass das zusätzliche Segment eine Anfrage an `/v1/v1/messages` bewirkt, die mit folgendem Fehler fehlschlägt:

```
not found: POST "https://api.lmuai.com/v1/v1/messages": 404 Not Found
```

Das ist das Gegenteil von `openai-compat` (das `/v1` benötigt) — verwechsle sie nicht.

</Callout>

</Tab>
</Tabs>

<Callout type="warn" title="Konfigurationsdateien sind vertrauenswürdiger Code">

Eine offizielle Warnung: `crushrc` wird mit deinen Shell-Rechten ausgeführt, bevor die Oberfläche erscheint, und jedes `$(...)` in `crush.json` wird beim Laden ausgeführt. **Starte Crush nicht in einem Verzeichnis, dessen Konfiguration du nicht überprüft hast**, und führe keine `source`-Befehle auf Konfigurationsdateien unbekannter Herkunft aus.

</Callout>

## Loslegen

Starte Crush nach der Konfiguration neu:

```bash
crush
```

Wechsle innerhalb einer Sitzung das Modell mit:

```
/models
```

<Callout type="info" title="LMU-AI-Modelle fehlen unter /models?">

Die eingebaute Modellliste von Crush stammt aus der [Catwalk](https://github.com/charmbracelet/catwalk)-Datenbank, die keine LMU-AI-Modell-IDs enthält. Du musst sie zuerst mit `model add <provider>/<model-id>` registrieren — sie erscheinen nach einem Neustart in der `/models`-Liste.

</Callout>

## Veraltete JSON-Konfiguration

<Callout type="warn" title="crush.json ist offiziell veraltet">

Crush verwendete ursprünglich `crush.json`, das nun **veraltet** ist — die Maintainer haben erklärt, dass sie es weiterhin unterstützen werden, aber neue Konfigurationsoptionen nur zur Bash-Konfiguration (`crushrc`) hinzugefügt werden. Viele Tutorials lehren immer noch das JSON-Format, aber **neue Einrichtungen sollten `crushrc` verwenden, wie oben gezeigt**.

Du hast bereits eine JSON-Konfiguration und möchtest migrieren? Starte Crush und bitte es einfach in normaler Sprache, sie für dich zu konvertieren.

</Callout>

Wenn du JSON verwenden möchtest, sieht das Format so aus (in einer `crush.json` in deinem Projektverzeichnis oder unter `~/.config/crush/`):

```json
{
  "$schema": "https://charm.land/crush.json",
  "providers": {
    "lmuai": {
      "id": "lmuai",
      "name": "LMU AI",
      "type": "openai-compat",
      "base_url": "https://api.lmuai.com/v1",
      "api_key": "sk-your-lmu-ai-api-key",
      "models": [
        {
          "id": "claude-opus-5",
          "name": "Claude Opus 5",
          "context_window": 200000,
          "default_max_tokens": 32000
        }
      ]
    }
  }
}
```

<Callout type="warn" title="Lasse type und models in JSON nicht weg">

Nur `id` / `name` / `base_url` / `api_key` funktioniert nicht: `type` entscheidet, welches Protokoll verwendet wird (das Weglassen führt zu einer Standard-Vermutung), und `models` entscheidet, was du unter `/models` auswählen kannst. Das ist der häufigste Grund, warum ein kopiertes Minimalbeispiel fehlschlägt.

</Callout>

## Hinweise

- Die Konfigurationsdatei ist `~/.config/crush/crushrc` (`%USERPROFILE%\.config\crush\crushrc` unter Windows); `~/.local/share/crush/crush.json` ist maschinenverwalteter Zustand — **bearbeite sie nicht**
- Verwende `--type openai-compat` für den OpenAI-kompatiblen Endpunkt von LMU AI (**nicht** `openai`) und `--type anthropic` für das Anthropic-Protokoll
- **Die beiden Typen nehmen gegensätzliche `--base-url`-Formen an**: `anthropic` nimmt `https://api.lmuai.com` (kein `/v1`), während `openai-compat` `https://api.lmuai.com/v1` nimmt (mit `/v1`). Das Hinzufügen von `/v1` auf der Anthropic-Seite führt zu `/v1/v1/messages` und einem 404
- Gib für den API-Schlüssel einfach den in der LMU-AI-Konsole generierten `sk-`-Schlüssel ein
- LMU-AI-Modelle sind nicht in der eingebauten Liste von Crush enthalten, daher müssen sie mit `model add` registriert werden, bevor sie unter `/models` erscheinen
