[api-image](https://github.com/yc-duan/api-image) مهارة Codex مجتمعية تعيد توليد الصور لـ **تطبيق Codex في وضع API**: فالمولّد المدمج imagegen غير متاح عند تسجيل الدخول بمفتاح API، لذا تستدعي نقطة نهاية الصور المتوافقة مع OpenAI التي تُعدّها بنفسك، وتحاكي تدفّق النسخة الويب — يفهم النموذج الرئيسي الطلب، ويبحث أو يحلّل الصور المرجعية عند الحاجة، ثم يستدعي نموذج الصور.

وبمجرد توجيهها إلى LMU AI فإنها تقرأ الإعدادات الموجودة أصلاً في دليل Codex الخاص بك، **دون إعداد إضافي لعنوان URL أساسي أو مفتاح**.

<Callout type="warn" title="هذه مهارة مجتمعية من طرف ثالث، وليست مكوّناً رسمياً من LMU AI">

- تعمل كسكربت Python على جهازك، و**تقرأ المفتاح من `~/.codex/auth.json`**، وترسل مطالبتك (بالإضافة إلى أي صور مرجعية) إلى المزوّد المُعدّ. تأكّد من ارتياحك لذلك قبل التثبيت
- تتطلّب **Python 3.11 أو أحدث**: يحلّل السكربت `config.toml` باستخدام `tomllib`، والإصدار الأقدم من Python يفشل فوراً مع `ModuleNotFoundError: No module named 'tomllib'`
- المستودع مرخّص بـ MIT، ويصفه المؤلف بأنه مهارة شخصية منقّحة — يتفاوت التوافق بين المزوّدين، لذا اعتبر رسائل الأخطاء الفعلية مصدر الحقيقة

</Callout>

## المتطلبات المسبقة

### 1. تطبيق Codex متصل بالفعل بـ LMU AI

اتبع [تطبيق Codex (سطح المكتب)](./codex-app) لإنشاء `~/.codex/config.toml` و`~/.codex/auth.json` — أي أن تطبيق Codex يستطيع بالفعل إجراء محادثة عادية.

لا تخزّن api-image أي بيانات اعتماد خاصة بها؛ فعند التشغيل تقرأ هذين الملفين تحديداً:

| ما تقرأه | من أين | القيمة من دليل هذا الموقع |
|------|------|------|
| مفتاح API | `OPENAI_API_KEY` في `~/.codex/auth.json` | مفتاح `sk-` المُولَّد في وحدة تحكم LMU AI |
| المزوّد الحالي | `model_provider` في `~/.codex/config.toml` | `codex` |
| نقطة النهاية | `[model_providers.<provider>].base_url` | `https://api.lmuai.com` |

ثم تستدعي `<base_url>/images/generations` (نص إلى صورة) و`<base_url>/images/edits` (صورة إلى صورة / ملء).

### 2. Python 3.11+

```bash
python3 --version
# needs to print 3.11 or later; older versions fail with "No module named 'tomllib'"
```

ثبّته أو رقّه باستخدام Homebrew على macOS:

```bash
brew install python@3.12
```

على Windows، نزّل مثبّتاً لإصدار 3.11+ من [python.org](https://www.python.org/downloads/)، أو شغّل:

```powershell
winget install Python.Python.3.12
```

<Callout type="warn" title="انتبه عند تثبيت عدة إصدارات من Python">

يشغّل Codex السكربت بأي مفسّر يجده. إن كان `python3 --version` لا يزال يشير إلى إصدار قديم 3.9، فستواجه خطأ `tomllib` أعلاه — بعد الترقية، تأكّد من أن `python3` (أو `python3.12`) هو فعلاً 3.11+. إن كان لديك عدة إصدارات مثبتة جنباً إلى جنب، فسمِّ المفسّر في المحادثة، مثلاً "شغّل سكربت api-image بـ python3.12".

</Callout>

لا حاجة لأي أوامر بعد ذلك — فقط اطلب بلغة عادية، تماماً كما تفعل عادةً:

<Tabs items={['نص إلى صورة', 'صورة مرجعية / صورة إلى صورة', 'الملء', 'ابحث أولاً ثم ارسم']}>
<Tab value="نص إلى صورة">

```text
Use api-image to generate a 2048x1152 cinematic photo: a rainy Tokyo street at night, neon reflections, realistic photography style.
```

</Tab>
<Tab value="صورة مرجعية / صورة إلى صورة">

```text

```

</Tab>
<Tab value="الملء">

```text
Change the red cup in this image to green, keeping the original shape, composition and lighting, with no text added.
```

</Tab>
<Tab value="ابحث أولاً ثم ارسم">

```text

```

</Tab>

القيم الافتراضية هي `2048x1152`، و`quality` عالية، ونموذج `gpt-image-2`. اطلب أي شيء آخر مباشرةً:

```text
Use api-image to generate a 1024x1024 flat illustration, quality low, two images, saved to ./public/cover.png
```

<Callout type="info" title="تُحفظ الملفات المولَّدة في دليل العمل الحالي">

بدون مسار إخراج، تُكتب الصور في دليل العمل الحالي لـ Codex بأسماء مثل `provider-image-20260918-153512.png`. عندما تطلب عدة صور، تكتسب أسماء الملفات `-v1` و`-v2` وهكذا. لا تلتزم بها بالخطأ — سمِّ مساراً صريحاً إن أردتها في مكان ثابت.

</Callout>

## الخيارات الشائعة

يمرّرها Codex عند استدعائه للمهارة، لذا كل ما عليك هو وصف ما تريده بلغة عادية؛ ومعرفة المتاح تساعدك على صياغته بدقة:

| الخيار | ملاحظات |
|------|------|
| `--model` | الافتراضي `gpt-image-2` |
| `--size` | الافتراضي `2048x1152`؛ وأيضاً `1024x1024`، و`1024x1536`، و`3840x2160`، و`auto` وغيرها — يجب أن تكون كلتا الحافتين من مضاعفات 16، والحافة الطويلة 3840 على الأكثر، ونسبة العرض إلى الارتفاع ليست أعرض من 3:1 |
| `--quality` | `low` / `medium` / `high` (الافتراضي) / `auto` |
| `--n` | عدد الصور لكل مطالبة، 1–10 |
| `--output-format` | `png` (الافتراضي) / `jpeg` / `webp` |
| `--image` / `--mask` | الصور المرجعية والأقنعة، حتى 16؛ توفير صورة مرجعية يبدّل تلقائياً إلى نقطة نهاية التحرير |
| `--base-url` | يتجاوز نقطة النهاية لهذا الاستدعاء الواحد فقط، مثلاً `https://api.lmuai.com/v1` |
| `--api-key-env` | يقرأ المفتاح من متغيّر بيئة مسمّى (أكثر أماناً من `--api-key`) |
| `--codex-home` | يشير إلى دليل Codex محدد، الافتراضي `~/.codex` |

<Callout type="info" title="base_url ونقطة النهاية الكاملة لـ LMU AI">

توثّق LMU AI عنوانها الأساسي المتوافق مع OpenAI *مع* `/v1` (نقطة النهاية الكاملة هي `https://api.lmuai.com/v1/images/generations`)، بينما يستخدم `config.toml` في دليل Codex اسم المضيف المجرّد — تدمجهما هذه المهارة كما هما ولا تضيف `/v1` بنفسها. تقبل LMU AI كلا الصيغتين، لذا **إن اتبعت دليل هذا الموقع فلا شيء لتغييره**؛ وإن كنت تفضّل كتابة نقطة النهاية الموثّقة بالكامل، فأضف جملة في المحادثة وستمرّر `--base-url` لذلك الاستدعاء:

```text
Use api-image to generate ..., with base_url https://api.lmuai.com/v1
```

</Callout>

## النماذج المدعومة

| معرّف النموذج | ملاحظات |
|------|------|
| `gpt-image-2` | النموذج الافتراضي للمهارة، يغطي نص إلى صورة، وصورة إلى صورة، والملء |

لا توجد قائمة سماح لـ `--model` — تُرسل معرّفات نماذج الصور الأخرى كما هي، وأمر عملها متروك لـ LMU AI (تحقق من "النماذج المتاحة" لمجموعتك). لقدرات وحدود `gpt-image-2`، انظر [واجهة برمجة صور GPT](/ar/docs/api/gpt-image): إنها لا تدعم الخلفيات الشفافة، وينبغي عدم إرسال `input_fidelity`.

## الأخطاء الشائعة

| نص الخطأ | السبب | الإصلاح |
|------|------|------|
| `ModuleNotFoundError: No module named 'tomllib'` | Python الذي يشغّل السكربت أقدم من 3.11 | رقّه إلى 3.11+، أو سمِّ مفسّراً أحدث |
| `OPENAI_API_KEY is missing in .../auth.json` | `auth.json` غائب أو لا يحتوي على مفتاح | أعدّه وفق [دليل تطبيق Codex](./codex-app)، أو مرّر مفتاحاً بـ `--api-key-env` |
| `Missing required file: .../config.toml` | لا يوجد `config.toml` في دليل Codex | كما أعلاه — اجعل تطبيق Codex يتحدث أولاً |
| `model_not_found` (HTTP 404) | مجموعة مفتاحك لا تكشف نموذج الصور ذاك | تحقق من قائمة نماذج المجموعة في وحدة التحكم |
| HTTP 403 | توليد الصور غير مفعّل للمجموعة | تواصل مع المسؤول أو بدّل المجموعات |
| HTTP 401 | مفتاح غير صالح | تحقق من أن مفتاح `sk-` في `auth.json` مكتمل |

لمزيد من خرائط أخطاء نقطة نهاية الصور، انظر [واجهة برمجة صور GPT](/ar/docs/api/gpt-image).

## ملاحظات

- هذه **مهارة مجتمعية من طرف ثالث** (بترخيص MIT، المستودع [yc-duan/api-image](https://github.com/yc-duan/api-image))، وليست مكوّناً رسمياً من LMU AI؛ تُجري الطلبات بصفتك وتقرأ ملفك المحلي `~/.codex/auth.json`
- تحتاج إلى **Python 3.11+**؛ يأتي macOS بـ Python 3.9 باسم `python3`، الذي يفشل فوراً مع `No module named 'tomllib'`
- لا تلصق مفتاحك أبداً في محادثة أو مستودع أو لقطة شاشة؛ ولتبديل المفاتيح مؤقتاً، اقرأ واحداً من متغيّر بيئة بـ `--api-key-env` بدلاً من `--api-key`، الذي يترك النص العادي في سجل الأوامر وقائمة العمليات
- يكون الإخراج افتراضياً في **دليل العمل الحالي** — لا تلتزم به في مستودعك بالخطأ
- `--size` ليس ضماناً قاطعاً: قد يقوم المصدر بتطبيع الأبعاد (أنتج طلب `1024x1024` صورة بحجم 1370×1148 في اختبارنا)، لذا اقرأ حجم الإخراج الفعلي واقتصّ إن احتجت إلى بكسلات دقيقة
- تحميل صورة إلى صورة يرفع صورك المرجعية إلى الخدمة المصدر — انتبه لحقوق الطبع والخصوصية
