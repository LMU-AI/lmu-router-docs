## Erreurs courantes

**Erreur : après configuration, vous obtenez une erreur 401 indiquant que la clé est incorrecte**

Cause : la requête est toujours envoyée au backend officiel d'OpenAI plutôt qu'à notre relais API, ou vous n'avez pas redémarré l'outil pour recharger le fichier de configuration.

Solution : suivez à nouveau le guide pour **créer ou remplacer** les deux fichiers `config.toml` et `auth.json`, puis redémarrez l'outil IDE.

<Callout type="info" title="Lorsque vous rencontrez une erreur">

Faites une capture d'écran du message d'erreur et traduisez-le — vous pourrez ainsi identifier vous-même la cause de l'erreur !

</Callout>

## Configuration

### Étape 1 — Créer / écraser les fichiers de configuration

Emplacement des fichiers de configuration :
- **Mac/Linux** : le répertoire `~/.codex/`
- **Windows** : le répertoire `C:\users\VotreNomUtilisateur\.codex\`

<Callout type="warn" title="Remarque pour Windows">

Si vous vous êtes précédemment connecté avec le compte officiel ou une autre plateforme, déconnectez-vous d'abord, puis configurez !

</Callout>

Si vous n'avez pas de dossier `.codex`, créez-le avec une commande de terminal :

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

```powershell
# Windows (run in the terminal)
rm -rf C:\users\YourUsername\.codex
mkdir C:\users\YourUsername\.codex
```

### Étape 2 — Écrire config.toml

Dans le répertoire `.codex`, créez ou écrasez `config.toml` :

```toml
model_provider = "OpenAI"
model = "gpt-5.4"
review_model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
network_access = "enabled"
windows_wsl_setup_acknowledged = true
model_context_window = 1000000
model_auto_compact_token_limit = 900000

[model_providers.OpenAI]
name = "OpenAI"
base_url = "https://api.lmuai.com"
wire_api = "responses"
requires_openai_auth = true
```

### Étape 3 — Écrire auth.json

Dans le répertoire `.codex`, créez ou écrasez `auth.json` :

```json
{
  "OPENAI_API_KEY": "your sk- key generated in the console"
}
```

Une fois configuré, ouvrez VS Code, Cursor ou Trae, et l'extension Codex qui s'y trouve se connectera automatiquement.

## Installer l'extension Visual Studio Code

### Installer l'extension

1. Ouvrez VS Code et ouvrez d'abord un dossier de projet comme espace de travail (**sinon une fenêtre contextuelle vous demandera d'ouvrir un dossier de projet !**)
2. Cliquez sur le panneau des extensions à gauche (l'icône Extensions)
3. Recherchez **Codex**, trouvez l'extension officielle d'OpenAI « Codex – OpenAI's coding agent », et cliquez sur Installer
4. Après l'installation, une entrée Codex apparaît dans la barre latérale gauche (sinon, cherchez en haut à droite de l'interface)

### Se déconnecter de l'ancien compte

<Callout type="warn" title="Important">

Si vous vous êtes précédemment connecté avec le compte officiel ou une autre plateforme, déconnectez-vous d'abord, puis configurez !

</Callout>

1. Cliquez sur l'icône des paramètres en haut à droite du panneau Codex
2. Cliquez sur **Log out** pour vous déconnecter

### Terminer la configuration

Après avoir configuré `config.toml` et `auth.json`, rouvrez l'extension Codex et cliquez sur **Continue** pour terminer le processus de connexion.

<Callout type="info" title="À propos de l'affichage des modèles">

Le modèle GPT-5.3 n'apparaît pas dans la liste déroulante ; survolez « Custom » pour voir le modèle actuellement utilisé.

Vous pouvez également vérifier le modèle réellement demandé dans la console sous « Enregistrements d'utilisation ».

</Callout>

## Vous souhaitez utiliser Claude ou les modèles chinois ?

Si vous utilisez uniquement Trae et que votre objectif est d'utiliser des modèles comme **Claude / GLM / Qwen**, vous n'avez pas besoin de l'extension Codex — la [Configuration native des modèles Trae](/fr/docs/tools/trae) (protocole Anthropic, il suffit de remplir quelques champs dans l'interface graphique) est plus simple.
