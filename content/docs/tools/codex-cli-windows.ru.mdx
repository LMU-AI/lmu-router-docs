После установки Codex CLI вручную создайте один файл конфигурации — `config.toml` (ключ указывается внутри него в заголовке запроса), — чтобы подключиться к API LMU AI; сторонние инструменты настройки не нужны.

---

## Шаг 1 — Установите Windows Terminal

В Windows для Codex CLI рекомендуем использовать **Windows Terminal** вместо CMD — он поддерживает несколько окон и удобнее.

- Загрузка с китайского облачного диска (рекомендуется, быстро): [https://www.ilanzou.com/s/MzWnpE05](https://www.ilanzou.com/s/MzWnpE05)
- Загрузка с GitHub: [https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0](https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0)

Скачайте `Microsoft.WindowsTerminal_1.23.20211.0_x64.zip`, распакуйте архив и дважды щёлкните `WindowsTerminal.exe` для запуска — удобно сразу создать ярлык на рабочем столе.

## Шаг 2 — Установите Node.js

> Если он уже установлен, этот шаг можно пропустить; проверить можно командой: `node -v`

Требуется **Node.js 20+** — загрузка: [https://nodejs.org/en/download](https://nodejs.org/en/download)

При установке обязательно отметьте пункт **«Automatically install the necessary tools»**.

После установки проверьте в терминале:

```bash
node -v
# A version number (e.g. v24.4.1) means it installed correctly
```

<Callout type="info" title="Особый случай">

Если `node.js` не установлен или вы устанавливали его раньше, но окружение настроено некорректно, скачайте и переустановите его один раз, затем заново откройте терминал.

</Callout>

**Если возникает ошибка о блокировке выполнения скриптов, выполните следующую команду:**

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## Шаг 3 — Установите Codex CLI

```bash
npm i -g @openai/codex
```

Если возникают проблемы с сетью, сначала переключитесь на китайское зеркало, а затем установите:

```bash
npm config set registry https://registry.npmmirror.com
npm i -g @openai/codex
```

Проверьте установку:

```bash
codex --version
# A version number means it installed correctly
```

## Шаг 4 — Создайте файлы конфигурации

Каталог конфигурации — **`C:\users\your-username\.codex\`** (создайте его, если он отсутствует; старые файлы перезапишите). Создайте/перезапишите в нём `config.toml`:

### config.toml

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

<Callout type="warn" title="Ключ указывается в заголовке запроса">

- Замените в последней строке «your sk- key generated in the console» на свой ключ `sk-`, **сохранив один пробел между `Bearer` и ключом**, например `Authorization = "Bearer sk-xxxx"`
- Разместите секцию `[model_providers.codex.http_headers]` в **самом конце** файла, чтобы после неё не было других настроек
- Новым версиям Codex больше не нужен `auth.json`. Если вы создали его по старой инструкции, его можно безболезненно оставить или удалить (оставьте, если используете [навык генерации изображений Codex App](/ru/docs/tools/codex-api-image))
- Если в вашей старой конфигурации в секции `[model_providers.codex]` есть `requires_openai_auth = true`, просто удалите эту строку

</Callout>

## Шаг 5 — Запустите Codex CLI

Сохранив файлы конфигурации, заново откройте терминал и выполните следующую команду, чтобы запустить Codex и войти автоматически:

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

Или в краткой форме:

```bash
codex --yolo
```

> Эта команда запуска пропускает подтверждения безопасности, поэтому каждый автоматически выполняемый шаг подтверждать не нужно.

При успешном запуске в интерфейсе отображается текущая модель — `gpt-5.4 xhigh` (модель, заданная полем `model` в `config.toml`).

## Включение контекста 1M в Codex (опционально)

`gpt-5.4` поддерживает **длинное окно контекста на 1M токенов** (по умолчанию только 272K), что полезно для анализа очень больших репозиториев, разбора длинных логов, рефакторинга сразу по нескольким файлам и похожих задач. Codex **не** включает окно 1M по умолчанию — его нужно объявить явно в `config.toml`.

### Как настроить: добавьте две строки в config.toml

Откройте `C:\users\your-username\.codex\config.toml` и добавьте следующее на **верхнем уровне** (до любой `[секции]`, например сразу после `model = "gpt-5.4"`):

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Сохраните файл, заново откройте терминал и снова войдите в Codex, чтобы применить изменения.

**Описание полей**

| Поле | Назначение |
|------|------|
| `model_context_window` | Объявляет доступное окно контекста модели в токенах; `1000000` — это 1M. Если не задано, используется значение модели по умолчанию (272K) |
| `model_auto_compact_token_limit` | Порог в токенах, при котором запускается автоматическое сжатие истории (auto-compact); задайте примерно 90% от окна (`900000` для 1M). Значения выше 90% окна Codex ограничивает, поэтому указывать больше бессмысленно |

### Проверьте, что настройка применилась

Снова войдя в Codex, введите `/status` и проверьте, показывает ли `context window` около 1M (в некоторых версиях отображается около 950K — это зарезервированный Codex запас в 5%). Также можно использовать `/statusline`, чтобы вывести расход контекста в строку состояния и следить за ним в реальном времени.

### Если вы используете CC Switch

Если вы управляете конфигурацией Codex через [CC Switch](/ru/docs/tools/cc-switch), добавьте те же две строки в его редакторе конфигурации Codex и примените изменения — результат будет таким же:

![Установка model_context_window = 1000000 и model_auto_compact_token_limit = 900000 в конфигурации Codex в CC Switch для включения длинного контекста на 1M токенов](/images/tools/codex/codex-ccs.png)

<Callout type="warn" title="Примечания по использованию">

- **Обязательно на верхнем уровне**: эти два поля не действуют внутри секции `[profiles.xxx]` (известное ограничение Codex); также указывайте их в пользовательском файле `C:\users\your-username\.codex\config.toml`, поскольку проектный `.codex\config.toml` может игнорироваться
- **Поддержка моделей**: `gpt-5.4` и `gpt-5.5` поддерживают 1M через канал API; модели вроде `gpt-5.3-codex` ограничены 272K, и никакое значение в конфигурации не может превысить собственный лимит модели
- **Выше стоимость**: чем длиннее контекст, тем больше токенов расходует каждый запрос; часть выше 272K тарифицируется по более высокому тарифу длинного контекста, поэтому не оставляйте эту настройку включённой, кроме очень длинных задач
- **Различия версий**: некоторые новые версии Codex сначала берут размер окна из каталога моделей; если `/status` по-прежнему показывает старое значение, обновитесь до последней версии (`npm i -g @openai/codex@latest`) и повторите попытку

</Callout>
