Codex CLI をインストールしたくなく、**Codex App デスクトップクライアント**だけを使いたい場合は、この方法に従ってください。

<Callout type="warn" title="注意">

- 以前に自分のアカウントでサインインしていた場合は、まず Codex App で**現在のアカウントからサインアウト**してから、再設定してください。
- API を切り替えると、それまでのチャット履歴は表示されなくなります（アカウント方式のチャット履歴はローカルではなく GPT アカウントの領域に保存されています）。
- **API ログインに切り替えた後は、以降のチャット履歴はすべてローカルに保存されるので失われません！**

</Callout>

---

## ステップ 1 — 設定ファイルを作成する

設定ファイルの場所：
- **Mac/Linux**：ホームディレクトリ（`~`）内の `.codex` フォルダ
- **Windows**：`C:\users\your-username\.codex\`

フォルダがすでに存在する場合は、古い設定の干渉を避けるため、中の `config.toml`（および以前のガイドで残った `auth.json`）を削除して作り直すのがおすすめです。

**ターミナルコマンドでフォルダを作成する：**

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

`.codex` フォルダ内に `config.toml` を作成します。

### config.toml

サービスプロバイダーを設定します。API キーはファイル末尾のリクエストヘッダーに記述します：

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

最後の行をご自身の `sk-` キーに置き換えてください。`Bearer` とキーの間にはスペースを 1 つ入れます。`[model_providers.codex.http_headers]` セクションはファイルの最後に置き、その後に他の設定を書かないでください。

<Callout type="info">

通常はホームディレクトリ内の `.codex` フォルダにあります。そこに `.codex` フォルダが見つからない場合は、手動でフォルダを作成し、その中に `config.toml` を作成してください。

設定ファイルの内容は [Codex CLI Mac/Linux セットアップガイド](/ja/docs/tools/codex-cli-mac) と同じです。そのガイドに従ってターミナルで作成することもでき、同じように Codex App を再起動すれば反映されます。

</Callout>

## ステップ 2 — Codex App を再度開く

設定ファイルを保存したら Codex App を開き直してください。自動的にサインインされ、そのまま使えるようになります。

---

## 1M コンテキストを有効にする（任意）

`gpt-5.4` は 1M トークンのロングコンテキストに対応していますが、デフォルトではオフになっています。上記の `config.toml` の**トップレベル**（どの `[section]` よりも前）に次の 2 行を追加し、Codex App を再起動してください：

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

各フィールドの意味、確認方法、注意点については [Codex で 1M コンテキストを有効にする](/ja/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional) をご覧ください。

## よくあるエラー

**Error 401、キーが正しくない：**

原因：リクエストが当社の API 中継ではなく、OpenAI の公式エンドポイントに送信されたままになっている、またはツールを再起動して設定ファイルを再読み込みしていない。

対処：ガイドに従って `config.toml` をもう一度作成または置き換えてから、アプリを開き直してください。

**Error 401 API_KEY_REQUIRED：**

原因：新しいバージョンの Codex では `auth.json` からキーを読み込まなくなっている可能性があり、リクエストにキーが含まれていません。

対処：上記のとおり `config.toml` の末尾に `[model_providers.codex.http_headers]` セクションを追加してください。詳しくは [FAQ · Issue 10](/ja/docs/guide/faq#issue-10) をご覧ください。
