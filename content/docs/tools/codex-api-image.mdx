[api-image](https://github.com/yc-duan/api-image) 是一个社区维护的 Codex Skill，用来给 **API 模式下的 Codex App** 补上生图能力：Codex 内置的 imagegen 在 API 登录时不可用，它改为调用你自己配置的 OpenAI 兼容图片接口，并尽量复刻网页版生图的流程——主模型先理解需求、必要时查资料或分析参考图、整理提示词，最后调用图片模型出图。

接上灵眸后，它读的就是你 Codex 目录里那套配置，**不需要额外的 base URL 或密钥设置**。

<Callout type="warn" title="这是第三方社区 Skill，不是灵眸官方组件">

- 它会在你本机以 Python 脚本运行，**读取 `~/.codex/auth.json` 里的密钥**，并携带提示词（以及你提供的参考图）向配置的 provider 发请求。安装前请自行确认可以接受
- 需要 **Python 3.11 或更高版本**：脚本用 `tomllib` 解析 `config.toml`，老版本 Python 会直接报 `ModuleNotFoundError: No module named 'tomllib'`
- 仓库为 MIT 协议，作者也说明这是「个人自用 Skill 的整理版」，不同 provider 兼容程度可能不同，遇到参数问题以实际报错为准

</Callout>

## 前提条件

### 1. Codex App 已经接入灵眸

按 [Codex App 桌面版](./codex-app) 的教程创建好 `~/.codex/config.toml` 与 `~/.codex/auth.json`，也就是能在 Codex App 里正常对话。

api-image 不保存任何凭据，它运行时读的正是这两个文件：

| 它要读的东西 | 来自哪里 | 本站教程里的值 |
|------|------|------|
| API Key | `~/.codex/auth.json` 的 `OPENAI_API_KEY` | 灵眸后台生成的 `sk-` 开头密钥 |
| 当前 Provider | `~/.codex/config.toml` 的 `model_provider` | `codex` |
| 接口地址 | `[model_providers.<provider>].base_url` | `https://api.lmuai.com` |

随后它请求 `<base_url>/images/generations`（文生图）与 `<base_url>/images/edits`（图生图 / 局部编辑）。

### 2. Python 3.11+

```bash
python3 --version
# 需要打印 3.11 或更高版本；旧版本会报 "No module named 'tomllib'"
```

macOS 用 Homebrew 安装或升级：

```bash
brew install python@3.12
```

Windows 到 [python.org](https://www.python.org/downloads/) 下载 3.11+ 安装包，或：

```powershell
winget install Python.Python.3.12
```

<Callout type="warn" title="系统里装了多个 Python 时要注意">

Codex 执行脚本时用的是它拿到的解释器。如果 `python3 --version` 仍指向 3.9 这类旧版本，会出现上面那个 `tomllib` 报错——升级后确认 `python3`（或 `python3.12`）已经是 3.11+；实在有多套 Python 并存，可以在对话里直接点名解释器，例如「用 python3.12 运行 api-image 的脚本」。

</Callout>

## 第一步：安装 Skill

把仓库克隆到 Codex 的 skills 目录（默认 `~/.codex/skills/`）：

<Tabs items={['macOS / Linux', 'Windows PowerShell']}>
<Tab value="macOS / Linux">

```bash
git clone https://github.com/yc-duan/api-image.git ~/.codex/skills/api-image
```

</Tab>
<Tab value="Windows PowerShell">

```powershell
git clone https://github.com/yc-duan/api-image.git "$env:USERPROFILE\.codex\skills\api-image"
```

如果你设置过 `CODEX_HOME` 环境变量，改用 `"$env:CODEX_HOME\skills\api-image"`。

</Tab>
</Tabs>

装好后**重启 Codex App**（或让它重新加载 Skills）。

装好后不需要敲任何命令，像平时一样用自然语言提要求即可：

<Tabs items={['文生图', '参考图 / 图生图', '局部编辑', '先查资料再生图']}>
<Tab value="文生图">

用 api-image 生成一张 2048x1152 的电影感照片：雨夜东京街头，霓虹反光，真实摄影风格。
```

</Tab>
<Tab value="参考图 / 图生图">

参考这张图的构图和人物姿势，生成一张暖色电影感插画，保持主体姿态，但不要照抄原图。
```

</Tab>
<Tab value="局部编辑">

```text

```

</Tab>
<Tab value="先查资料再生图">

```text
先查一下花江峡谷大桥的结构和地形参考，再生成一张高空俯视图，尽量保持真实桥型和峡谷环境。
```

默认输出 `2048x1152`、`quality` 为 `high`、模型为 `gpt-image-2`，需要别的参数直接说出来就行：

```text
用 api-image 生成一张 1024x1024 的扁平插画，画质 low，出 2 张，保存到 ./public/cover.png
```

<Callout type="info" title="生成的文件默认落在当前工作目录">

不给输出路径时，文件写到 Codex 的当前工作目录，命名形如 `provider-image-20260918-153512.png`。一次生成多张时会在文件名上加 `-v1`、`-v2` 之类的序号。别把它误提交进仓库——需要固定位置就在对话里指定路径。

</Callout>

## 常用参数

这些参数由 Codex 调用 Skill 时传入，你只要用自然语言描述需求即可；知道有哪些能力，指令能写得更准：

| 参数 | 说明 |
|------|------|
| `--model` | 默认 `gpt-image-2` |
| `--size` | 默认 `2048x1152`，也可用 `1024x1024`、`1024x1536`、`3840x2160`、`auto` 等；宽高需为 16 的倍数，长边不超过 3840，长宽比不超过 3:1 |
| `--quality` | `low` / `medium` / `high`（默认） / `auto` |
| `--n` | 每个提示词生成张数，1–10 |
| `--output-format` | `png`（默认） / `jpeg` / `webp` |
| `--image` / `--mask` | 参考图与遮罩图，最多 16 张；带参考图时自动走图片编辑端点 |
| `--base-url` | 只对本次调用临时覆盖接口地址，例如 `https://api.lmuai.com/v1` |
| `--api-key-env` | 从指定环境变量读取密钥（比 `--api-key` 更安全） |
| `--codex-home` | 显式指定 Codex 目录，默认 `~/.codex` |

<Callout type="info" title="base_url 与灵眸的完整端点">

灵眸文档里 OpenAI 兼容协议的 base URL 是带 `/v1` 的（完整端点 `https://api.lmuai.com/v1/images/generations`），而 Codex 教程里的 `config.toml` 写的是不带 `/v1` 的主机名——这个 Skill 会直接拼接，不自动补 `/v1`。两种写法灵眸都能接住，所以**按本站教程配好的用户无需改动配置**；想严格按文档的完整端点书写时，在对话里加一句即可，它会用 `--base-url` 覆盖本次调用：

```text
用 api-image 生成一张…，base_url 用 https://api.lmuai.com/v1
```

</Callout>

## 支持的模型

| 模型 ID | 说明 |
|------|------|
| `gpt-image-2` | Skill 的默认模型，支持文生图、图生图与局部编辑 |

`--model` 不做模型白名单，传其它图片模型 ID 也会照发，能否成功由灵眸这边决定（以你分组后台的「可用模型」为准）。`gpt-image-2` 的能力与限制见 [GPT 生图 API](/docs/api/gpt-image)：不支持透明背景，也不应传 `input_fidelity`。

## 常见报错

| 报错原文 | 原因 | 处理 |
|------|------|------|
| `ModuleNotFoundError: No module named 'tomllib'` | 运行脚本的 Python 低于 3.11 | 升级到 3.11+，或指定高版本解释器 |
| `OPENAI_API_KEY is missing in .../auth.json` | `auth.json` 不存在或没填密钥 | 按 [Codex App 教程](./codex-app) 补齐，或用 `--api-key-env` 临时传 |
| `Missing required file: .../config.toml` | Codex 目录里没有 `config.toml` | 同上，先让 Codex App 能正常对话 |
| `model_not_found`（HTTP 404） | 密钥所属分组没有开放该图片模型 | 在后台「可用模型」确认分组范围 |
| HTTP 403 | 分组未开启图片生成 | 联系管理员或改用支持图片的分组 |
| HTTP 401 | 密钥无效 | 检查 `auth.json` 里的 `sk-` 密钥是否完整 |

更多图片接口层面的报错对照见 [GPT 生图 API](/docs/api/gpt-image)。

## 注意事项

- 这是**第三方社区 Skill**（MIT 协议，仓库 [yc-duan/api-image](https://github.com/yc-duan/api-image)），不是灵眸官方组件；它以你的身份请求 provider，并会读取本机 `~/.codex/auth.json`
- 运行环境需要 **Python 3.11+**；macOS 自带的 `python3` 通常是 3.9，会直接报 `No module named 'tomllib'`
- 密钥不要粘进聊天、仓库或截图；需要临时换 Key 时用 `--api-key-env` 从环境变量读取，避免 `--api-key` 把明文留在命令行历史与进程列表里
- 生成结果默认写入**当前工作目录**，注意别把它提交到仓库
- `--size` 不是硬保证：上游可能对尺寸做归一化（实测请求 `1024x1024` 拿到的图是 1370×1148），需要固定像素时读取输出文件实际尺寸再裁切
- 图生图会把参考图上传到上游服务，注意版权与隐私
