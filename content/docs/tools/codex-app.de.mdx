Wenn du die Codex CLI nicht installieren möchtest und einfach nur den **Codex-App-Desktop-Client** verwenden willst, folge dieser Methode.

<Callout type="warn" title="Hinweis">

- Wenn du dich zuvor mit deinem eigenen Konto angemeldet hast, **melde dich zuerst vom aktuellen Konto ab** in der Codex App und konfiguriere dann neu.
- Nachdem du die API gewechselt hast, ist dein Chatverlauf verschwunden (der Chatverlauf vom Kontotyp wird im Bereich deines GPT-Kontos gespeichert, nicht lokal).
- **Nachdem du auf die API-Anmeldung umgestellt hast, wird der gesamte Chatverlauf ab dann lokal gespeichert und geht nicht verloren!**

</Callout>

---

## Schritt 1 — Erstelle die Konfigurationsdateien

Speicherort der Konfigurationsdatei:
- **Mac/Linux**: der Ordner `.codex` in deinem Home-Verzeichnis (`~`)
- **Windows**: `C:\users\dein-benutzername\.codex\`

Wenn der Ordner bereits existiert, ist es am besten, die darin enthaltenen `auth.json` und `config.toml` zu löschen und neu zu erstellen, um Störungen durch alte Konfigurationen zu vermeiden.

**Erstelle den Ordner mit einem Terminal-Befehl:**

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

Erstelle zwei Dateien im Ordner `.codex`:

### auth.json

Enthält deinen API-Schlüssel:

```json
{
  "OPENAI_API_KEY": "your sk- key generated in the console"
}
```

### config.toml

Konfiguriere den Dienstanbieter:

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"
requires_openai_auth = true
```

<Callout type="info">

Er befindet sich normalerweise im Ordner `.codex` in deinem Home-Verzeichnis. Wenn du den Ordner `.codex` dort nicht finden kannst, kannst du den Ordner manuell erstellen, zusammen mit `config.toml` und `auth.json`.

Die Inhalte der Konfigurationsdatei sind identisch mit der [Codex CLI Einrichtungsanleitung für Mac/Linux](/de/docs/tools/codex-cli-mac) — du kannst dieser Anleitung folgen, um sie im Terminal zu erstellen, und sie werden nach einem Neustart der Codex App genauso wirksam.

</Callout>

## Schritt 2 — Öffne die Codex App erneut

Nachdem du die Konfigurationsdateien gespeichert hast, öffne die Codex App erneut, und sie meldet sich automatisch an und ist einsatzbereit.

---

## Den 1M-Kontext aktivieren (optional)

`gpt-5.4` unterstützt einen langen Kontext von 1M Token, ist aber standardmäßig deaktiviert. Füge oben in der obigen `config.toml` auf der **obersten Ebene** (vor allen `[section]`-Abschnitten) zwei Zeilen hinzu und starte dann die Codex App neu:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Für die Bedeutung der Felder, wie du sie überprüfst, und Hinweise siehe [Den 1M-Kontext in Codex aktivieren](/de/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).

---

## Häufige Fehler

**Fehler 401, falscher Schlüssel:**

Ursache: Die Anfrage geht immer noch an den offiziellen Endpunkt von OpenAI statt an unser API-Relay, oder du hast das Tool nicht neu gestartet, um die Konfigurationsdatei neu zu laden.

Lösung: Folge der Anleitung erneut, um die Dateien `config.toml` und `auth.json` zu erstellen oder zu ersetzen, und öffne dann die App erneut.
