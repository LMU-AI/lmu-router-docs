Wenn Sie die Codex CLI nicht installieren möchten und einfach nur den **Desktop-Client Codex App** nutzen wollen, folgen Sie dieser Methode.

<Callout type="warn" title="Hinweis">

- Wenn Sie sich zuvor mit Ihrem eigenen Konto angemeldet haben, **melden Sie sich zuerst vom aktuellen Konto ab** in der Codex App und konfigurieren Sie dann neu.
- Nach dem Wechsel der API ist Ihr Chatverlauf verschwunden (der Chatverlauf vom Kontotyp wird im Bereich Ihres GPT-Kontos gespeichert, nicht lokal).
- **Nach dem Wechsel zur API-Anmeldung wird der gesamte Chatverlauf von da an lokal gespeichert und geht nicht verloren!**

</Callout>

---

## Schritt 1 — Konfigurationsdateien erstellen

Speicherort der Konfigurationsdatei:
- **Mac/Linux**: der Ordner `.codex` in Ihrem Home-Verzeichnis (`~`)
- **Windows**: `C:\users\your-username\.codex\`

Wenn der Ordner bereits existiert, ist es am besten, die darin enthaltene `config.toml` zu löschen (sowie eine eventuell aus der alten Anleitung übrig gebliebene `auth.json`) und sie neu zu erstellen, um Störungen durch alte Konfiguration zu vermeiden.

**Den Ordner mit einem Terminal-Befehl erstellen:**

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

Erstellen Sie `config.toml` im Ordner `.codex`.

### config.toml

Konfigurieren Sie den Dienstanbieter; der API-Schlüssel kommt in einen Request-Header ganz am Ende der Datei:

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

Ersetzen Sie die letzte Zeile durch Ihren `sk-`-Schlüssel und behalten Sie ein Leerzeichen zwischen `Bearer` und dem Schlüssel. Platzieren Sie den Abschnitt `[model_providers.codex.http_headers]` ganz am Ende der Datei, ohne weitere Einstellungen danach.

<Callout type="info">

Normalerweise befindet er sich im Ordner `.codex` in Ihrem Home-Verzeichnis. Wenn Sie den Ordner `.codex` dort nicht finden, können Sie den Ordner manuell erstellen und darin dann `config.toml` anlegen.

Die Inhalte der Konfigurationsdatei sind identisch mit der [Einrichtungsanleitung für Codex CLI Mac/Linux](/de/docs/tools/codex-cli-mac) — Sie können dieser Anleitung folgen, um sie im Terminal zu erstellen, und sie werden nach einem Neustart der Codex App genauso wirksam.

</Callout>

## Schritt 2 — Die Codex App erneut öffnen

Öffnen Sie nach dem Speichern der Konfigurationsdateien die Codex App erneut; sie meldet sich automatisch an und ist einsatzbereit.

---

## Den 1M-Kontext aktivieren (optional)

`gpt-5.4` unterstützt einen langen Kontext von 1M Token, ist aber standardmäßig deaktiviert. Fügen Sie zwei Zeilen auf der **obersten Ebene** der oben genannten `config.toml` hinzu (vor allen `[section]`-Abschnitten) und starten Sie dann die Codex App neu:

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Bedeutungen der Felder, Vorgehen zur Überprüfung und Einschränkungen finden Sie unter [Den 1M-Kontext in Codex aktivieren](/de/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).

## Häufige Fehler

**Fehler 401, falscher Schlüssel:**

Ursache: Die Anfrage geht noch an den offiziellen Endpunkt von OpenAI und nicht an unser API-Relay, oder Sie haben das Tool nicht neu gestartet, um die Konfigurationsdatei neu zu laden.

Lösung: Folgen Sie der Anleitung erneut, um `config.toml` zu erstellen oder zu ersetzen, und öffnen Sie dann die App erneut.

**Fehler 401 API_KEY_REQUIRED:**

Ursache: Neuere Codex-Versionen lesen den Schlüssel möglicherweise nicht mehr aus `auth.json`, sodass die Anfrage keinen Schlüssel mitführt.

Lösung: Fügen Sie den Abschnitt `[model_providers.codex.http_headers]` wie oben gezeigt am Ende von `config.toml` hinzu; siehe [FAQ · Issue 10](/de/docs/guide/faq#issue-10).
