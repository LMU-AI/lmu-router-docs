Si vous ne souhaitez pas installer le Codex CLI et préférez simplement utiliser le **client de bureau Codex App**, suivez cette méthode.

<Callout type="warn" title="Remarque">

- Si vous vous étiez déjà connecté avec votre propre compte, commencez par **vous déconnecter du compte actuel** dans la Codex App, puis refaites la configuration.
- Après le passage à l'API, votre historique de conversations disparaîtra (l'historique lié au compte est stocké dans l'espace de votre compte GPT, pas en local).
- **Une fois passé à la connexion par API, tout l'historique de conversations à partir de ce moment est enregistré en local et ne sera pas perdu !**

</Callout>

---

## Étape 1 — Créer les fichiers de configuration

Emplacement du fichier de configuration :
- **Mac/Linux** : le dossier `.codex` dans votre répertoire personnel (`~`)
- **Windows** : `C:\users\your-username\.codex\`

Si le dossier existe déjà, il est préférable de supprimer le `config.toml` qu'il contient (ainsi que tout `auth.json` resté de l'ancien guide) et de le recréer, afin d'éviter les interférences avec l'ancienne configuration.

**Créer le dossier avec une commande de terminal :**

```bash
# Mac/Linux
rm -rf ~/.codex && mkdir ~/.codex
```

Créez `config.toml` dans le dossier `.codex`.

### config.toml

Configurez le fournisseur de service ; la clé API se place dans un en-tête de requête tout à la fin du fichier :

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

Remplacez la dernière ligne par votre clé `sk-`, en conservant une espace entre `Bearer` et la clé. Placez la section `[model_providers.codex.http_headers]` tout à la fin du fichier, sans aucun autre réglage après elle.

<Callout type="info">

Il se trouve généralement dans le dossier `.codex` de votre répertoire personnel. Si vous ne trouvez pas le dossier `.codex` à cet endroit, vous pouvez le créer manuellement, puis y créer `config.toml`.

Le contenu du fichier de configuration est identique à celui du [guide de configuration Codex CLI Mac/Linux](/fr/docs/tools/codex-cli-mac) — vous pouvez suivre ce guide pour les créer dans le terminal, et ils prennent effet après redémarrage de la Codex App, exactement de la même façon.

</Callout>

## Étape 2 — Relancer la Codex App

Après avoir enregistré les fichiers de configuration, relancez la Codex App : la connexion se fera automatiquement et l'outil sera prêt à l'emploi.

---

## Activer le contexte de 1 M (facultatif)

`gpt-5.4` prend en charge un long contexte de 1 M de tokens, mais il est désactivé par défaut. Ajoutez deux lignes au **niveau racine** du `config.toml` ci-dessus (avant toute `[section]`), puis redémarrez la Codex App :

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

Pour la signification des champs, la méthode de vérification et les points d'attention, voir [Activer le contexte de 1 M dans Codex](/fr/docs/tools/codex-cli-mac#enabling-the-1m-context-in-codex-optional).

## Erreurs courantes

**Erreur 401, clé incorrecte :**

Cause : la requête part toujours vers le point de terminaison officiel d'OpenAI et non vers notre relais API, ou vous n'avez pas redémarré l'outil pour recharger le fichier de configuration.

Solution : reprenez le guide pour créer ou remplacer `config.toml`, puis relancez l'application.

**Erreur 401 API_KEY_REQUIRED :**

Cause : les versions récentes de Codex peuvent ne plus lire la clé depuis `auth.json`, la requête ne transporte donc aucune clé.

Solution : ajoutez la section `[model_providers.codex.http_headers]` à la fin de `config.toml` comme indiqué ci-dessus ; voir [FAQ · Problème 10](/fr/docs/guide/faq#issue-10).
