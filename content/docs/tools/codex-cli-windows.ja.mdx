Codex CLI をインストールしたあと、手動で設定ファイル `config.toml` を 1 つ作成するだけ（キーはその中のリクエストヘッダーに記述します）で LMU AI API に接続できます。サードパーティの設定ツールは不要です。

---

## ステップ 1 — Windows Terminal をインストール

Windows では、Codex CLI に CMD ではなく **Windows Terminal** を使うことをおすすめします。複数ウィンドウに対応しており、より便利です。

- 中国クラウドドライブからのダウンロード（推奨、高速）：[https://www.ilanzou.com/s/MzWnpE05](https://www.ilanzou.com/s/MzWnpE05)
- GitHub からのダウンロード：[https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0](https://github.com/microsoft/terminal/releases/tag/v1.23.20211.0)

`Microsoft.WindowsTerminal_1.23.20211.0_x64.zip` をダウンロードして解凍し、`WindowsTerminal.exe` をダブルクリックすると起動します。デスクトップにショートカットを作成しておくとよいでしょう。

## ステップ 2 — Node.js をインストール

> すでにインストール済みの場合はスキップできます。確認方法：`node -v`

**Node.js 20+** が必要です。ダウンロード：[https://nodejs.org/en/download](https://nodejs.org/en/download)

インストール時は必ず **「Automatically install the necessary tools」** にチェックを入れてください。

インストール後、ターミナルで確認します：

```bash
node -v
# A version number (e.g. v24.4.1) means it installed correctly
```

<Callout type="info" title="特殊なケース">

`node.js` がインストールされていない場合、または以前インストールしたが環境設定が正しくない場合は、もう一度ダウンロードして再インストールし、ターミナルを開き直してください。

</Callout>

**スクリプト実行がブロックされるエラーが出た場合は、以下のコマンドを実行してください：**

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## ステップ 3 — Codex CLI をインストール

```bash
npm i -g @openai/codex
```

ネットワークの問題が発生する場合は、先に中国国内のミラーに切り替えてからインストールしてください：

```bash
npm config set registry https://registry.npmmirror.com
npm i -g @openai/codex
```

インストールを確認します：

```bash
codex --version
# A version number means it installed correctly
```

## ステップ 4 — 設定ファイルを作成

設定ディレクトリは **`C:\users\your-username\.codex\`** です（存在しない場合は作成し、古いファイルは上書きしてください）。その中に `config.toml` を作成／上書きします：

### config.toml

```toml
model = "gpt-5.4"
model_reasoning_effort = "xhigh"
disable_response_storage = true
sandbox_mode = "danger-full-access"
windows_wsl_setup_acknowledged = true
approval_policy = "never"
file_opener = "vscode"
model_provider = "codex"
web_search = "cached"
suppress_unstable_features_warning = true

[history]
persistence = "save-all"

[tui]
notifications = true

[shell_environment_policy]
inherit = "all"
ignore_default_excludes = false

[sandbox_workspace_write]
network_access = true

[features]
plan_tool = true
apply_patch_freeform = true
view_image_tool = true
unified_exec = false
streamable_shell = false
rmcp_client = true
elevated_windows_sandbox = true

[profiles.auto-max]
approval_policy = "never"
sandbox_mode = "workspace-write"

[profiles.review]
approval_policy = "on-request"
sandbox_mode = "workspace-write"

[notice]
hide_gpt5_1_migration_prompt = true

[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"

[model_providers.codex.http_headers]
Authorization = "Bearer your sk- key generated in the console"
```

<Callout type="warn" title="キーはリクエストヘッダーに記述します">

- 最終行の「コンソールで生成した sk- キー」をご自身の `sk-` キーに置き換えてください。**`Bearer` とキーの間にはスペースを 1 つ入れたままにします**。例：`Authorization = "Bearer sk-xxxx"`
- `[model_providers.codex.http_headers]` セクションはファイルの **最後** に置き、そのあとに他の設定を書かないでください
- 新しいバージョンの Codex では `auth.json` は不要になりました。古いガイドに従って作成済みの場合、そのまま残しても問題ありませんし、削除しても構いません（[Codex App の画像生成スキル](/ja/docs/tools/codex-api-image)を使う場合は残してください）
- 古い設定の `[model_providers.codex]` セクションに `requires_openai_auth = true` がある場合は、その行を削除してください

</Callout>

## ステップ 5 — Codex CLI を起動

設定ファイルを保存したら、ターミナルを開き直して以下を実行すると、起動と自動サインインが行われます：

```bash
codex --dangerously-bypass-approvals-and-sandbox
```

または短縮形：

```bash
codex --yolo
```

> この起動コマンドはセキュリティ承認をスキップするため、自動実行される各ステップを個別に承認する必要がなくなります。

正常に起動すると、画面上の現在のモデルが `gpt-5.4 xhigh` と表示されます（`config.toml` の `model` フィールドで設定したモデルです）。

## Codex で 1M コンテキストを有効にする（任意）

`gpt-5.4` は **1M トークンのロングコンテキストウィンドウ** に対応しています（デフォルトは 272K のみ）。非常に大きなリポジトリのレビュー、長いログの解析、複数ファイルにまたがるリファクタリングなどに役立ちます。Codex はデフォルトでは 1M ウィンドウを有効にしないため、`config.toml` で明示的に宣言する必要があります。

### 設定方法：config.toml に 2 行追加する

`C:\users\your-username\.codex\config.toml` を編集し、以下を **トップレベル** に追加します（`[section]` より前、例えば `model = "gpt-5.4"` の直後）：

```toml
model_context_window = 1000000
model_auto_compact_token_limit = 900000
```

保存してターミナルを開き直し、Codex に再度入ると反映されます。

**フィールドの説明**

| フィールド | 用途 |
|------|------|
| `model_context_window` | モデルが使用できるコンテキストウィンドウをトークン単位で宣言します。`1000000` は 1M です。未設定の場合はモデルのデフォルト（272K）が使われます |
| `model_auto_compact_token_limit` | 履歴の自動圧縮（auto-compact）をトリガーするトークンのしきい値です。ウィンドウの約 90%（1M なら `900000`）に設定してください。ウィンドウの 90% を超える値は Codex 側で制限されるため、それより大きな数値を指定しても意味がありません |

### 反映されたか確認する

Codex に再度入ったあと `/status` と入力し、`context window` が 1M 前後になっているか確認してください（バージョンによっては約 950K と表示されます。これは Codex が確保する 5% の安全マージンによるものです）。`/statusline` を使ってステータスバーにコンテキスト使用量を追加し、リアルタイムで監視することもできます。

### CC Switch を使う場合

[CC Switch](/ja/docs/tools/cc-switch) で Codex の設定を管理している場合は、その Codex 設定エディタに同じ 2 行を追加して適用すれば、効果は同じです：

![CC Switch の Codex 設定で model_context_window = 1000000 と model_auto_compact_token_limit = 900000 を設定して 1M トークンのロングコンテキストを有効にする](/images/tools/codex/codex-ccs.png)

<Callout type="warn" title="利用上の注意">

- **必ずトップレベルに置くこと**：この 2 つのフィールドは `[profiles.xxx]` セクション内では反映されません（Codex の既知の制限）。また、プロジェクトレベルの `.codex\config.toml` は無視される可能性があるため、ユーザーレベルの `C:\users\your-username\.codex\config.toml` に記述してください
- **モデルの対応状況**：`gpt-5.4` と `gpt-5.5` は API チャネル経由で 1M に対応します。`gpt-5.3-codex` などのモデルは 272K が上限で、どのような設定値もモデル自身の上限を超えることはできません
- **コストの増加**：コンテキストが長いほど、1 リクエストあたりのトークン消費量が増えます。272K を超える部分はより高いロングコンテキスト料金で課金されるため、非常に長いタスク以外では有効にしたままにしないでください
- **バージョンによる差異**：一部の新しいバージョンの Codex はモデルカタログからウィンドウサイズを優先的に読み取ります。`/status` に古い値が表示され続ける場合は、最新版にアップグレード（`npm i -g @openai/codex@latest`）して再試行してください

</Callout>
