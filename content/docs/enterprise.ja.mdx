すでに AI 呼び出しを製品や社内ワークフローに組み込んでいるチーム向けに、個人プランとは別のエンタープライズプランをご用意しています。**Anthropic（Claude）** と **OpenAI（GPT）** の両プラットフォームを対象に、**Enterprise Standard / Enterprise Flagship** の 2 層にまたがり、合計 **6 SKU** を提供します。

## 私たちが解決する課題

チームが以下のいずれかに直面したことがあるなら、個人プランよりもエンタープライズプランのほうが適していることが多いです：

- **本番環境に影響する不安定さ**：時折の呼び出し失敗により、フォールバック・リトライ・監視を自前でコードに書かざるを得ない
- **柔軟性を欠くクォータ構成**：日次 / 週次パスでは、チームの同時・複数人・複数シナリオのニーズを支えきれない
- **遅いサポート対応**：障害発生時に何時間もサポートを待たされ、業務が停滞する
- **コンプライアンス資料の不足**：財務は請求書を、法務は契約書を必要としている
- **可視性の欠如**：各プロジェクトがどれだけのトークンを消費したか、誰が何を実行しているか、コストをどう配分すればよいかが分からない

## すべてのエンタープライズ層で共通の機能

どの層を選んでも、すべてのエンタープライズプランには以下が含まれます：

| 機能 | 説明 |
|------|------|
| **マルチソースルーティング + 自動フェイルオーバー** | [信頼性アーキテクチャ](/ja/docs/guide/reliability)を参照 |
| **99.5% 可用性目標 + 月次レポート** | エンタープライズ層は 99.5% の可用性目標をコミットし、月次の可用性レポートを提供します。[SLA セクション](/ja/docs/guide/reliability#service-level-sla)を参照 |
| **利用明細 API** | [/api/v1/usage エンドポイント](/ja/docs/api/usage-export)経由で、呼び出し明細・トークン消費量・コストを自動的に取得 |
| **コンテンツ非保持** | プロンプトと応答コンテンツは永続化されません。[データとプライバシー](/ja/docs/guide/privacy)を参照 |
| **契約書と請求書** | 調達契約の締結と適格請求書の発行に対応 |
| **1 つのキーで複数プラットフォーム** | 呼び出せるモデルは API キーのグループによって決まり、プロトコルとは独立しています。[API プロトコル](/ja/docs/guide/api-protocols)を参照 |

> より高い SLA と補償条件はビジネスチームと調整可能です。契約が優先します。

## FAQ

<Callout type="info" title="エンタープライズプランと個人プランは共存できますか？">

はい。1 つのアカウントで複数のプランを同時に保有でき、呼び出しは API キーのグループによってルーティングされます — [API プロトコル · プロトコルと利用可能モデルは別物](/ja/docs/guide/api-protocols#protocol-vs-models)を参照してください。

</Callout>

<Callout type="info" title="Claude と GPT を混在させられますか？">

1 つの API キーで呼び出せるモデルはそのグループによって決まります：Anthropic プラットフォームの SKU をご発注いただいた場合は Claude 系モデルを呼び出せ、OpenAI プラットフォームの SKU をご発注いただいた場合は GPT 系モデルを呼び出せます。両プラットフォームが必要な場合は、対応する SKU をそれぞれご発注ください。

</Callout>

<Callout type="info" title="より高い SLA や補償条件はどう交渉すればよいですか？">

エンタープライズ層のデフォルトである 99.5% の可用性目標を超えて、より高い SLA や明示的な補償条件が必要な場合は、ビジネス窓口を通じて調整してください。契約が優先します。

</Callout>
