Anthropic Messages 요청의 `tools`에 `web_search` 도구를 추가하면 Claude가 필요할 때 웹을 검색합니다. 검색 여부, 검색어, 검색 횟수는 Claude가 결정하며, 검색은 서버에서 실행됩니다. **최종 답변과 출처 링크가 포함된 문장 단위 인용이 같은 응답으로 반환되므로** 검색을 직접 실행하거나 도구 호출 루프를 작성할 필요가 없습니다.

<Callout type="warn" title="Claude-MAX-高倍率分组（不限制） 그룹의 API 키를 사용하세요">

웹 검색에는 **Claude-MAX-高倍率分组（不限制）** 그룹의 API 키를 사용하세요. 이 그룹은 정상적으로 검색하고 문장 단위 인용을 반환하는 것이 테스트로 확인되었습니다.

**Claude-Pro 超值版** 그룹은 현재 `Search results for "..."`로 시작하는 원시 검색 결과만 반환하며, 모델의 답변과 인용이 없습니다. 웹 검색에는 사용하지 마세요.

</Callout>

## 1. 개요 [#overview]

| 항목 | 값 |
|---|---|
| Base URL | `https://api.lmuai.com` |
| 엔드포인트 | `POST /v1/messages` (Anthropic Messages 프로토콜) |
| 인증 | `x-api-key: <your sk- API key>` 또는 `Authorization: Bearer <your sk- API key>` |
| 필수 헤더 | `anthropic-version: 2023-06-01`, `content-type: application/json` |
| 검색 활성화 | 요청 본문에 `"tools": [{"type": "web_search_20250305", "name": "web_search"}]` 추가 |
| 테스트된 모델 | `claude-sonnet-5-5`, `claude-opus-5-5` |

## 2. 빠른 시작 [#quick-start]

```bash
curl https://api.lmuai.com/v1/messages \
  -H "x-api-key: $LMU_API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-sonnet-5-5",
    "max_tokens": 4096,
    "messages": [
      {"role": "user", "content": "What is the weather in Beijing today? Search the web and cite your sources."}
    ],
    "tools": [
      {"type": "web_search_20250305", "name": "web_search", "max_uses": 3}
    ]
  }'
```

## 3. 도구 파라미터 [#tool-parameters]

```json
{
  "type": "web_search_20250305",
  "name": "web_search",
  "max_uses": 3,
  "allowed_domains": ["weather.com.cn"]
}
```

| 필드 | 필수 | 설명 |
|---|---|---|
| `type` | 예 | 도구 버전. `web_search_20250305`를 권장합니다. 아래 참고 사항을 확인하세요 |
| `name` | 예 | 항상 `web_search` |
| `max_uses` | 아니요 | 이 요청에서 허용되는 최대 검색 횟수. 초과하면 추가 검색은 `max_uses_exceeded` 오류를 반환하며(8절 참고), Claude는 이미 얻은 결과로 답변합니다 |
| `allowed_domains` | 아니요 | 이 사이트의 결과만 사용합니다. `https://` 없이 도메인만 입력하세요(예: `["weather.com.cn"]`). 테스트에서 모든 결과가 해당 도메인 또는 그 하위 도메인에서 나왔습니다 |
| `blocked_domains` | 아니요 | 이 사이트를 제외합니다. 테스트에서 해당 도메인은 결과에 더 이상 나타나지 않았습니다 |
| `user_location` | 아니요 | 위치 정보. `type`은 반드시 `approximate`여야 하며, `city`, `region`, `country`, `timezone`은 선택 사항입니다. 테스트에서 오류 없이 받아들여졌지만 결과가 위치에 따라 눈에 띄게 조정되지는 않았습니다. 지역 정보가 필요할 때는 프롬프트에 도시 이름을 적는 편이 더 확실합니다 |

<Callout type="warn" title="allowed_domains와 blocked_domains는 둘 중 하나만 사용하세요">

둘을 함께 보내면 요청이 400으로 실패하거나, 200을 반환하면서 검색 결과가 비어 있을 수 있습니다(반복 테스트에서는 후자가 나타났습니다). 둘 중 하나만 남기세요.

</Callout>

**도구 버전에 대해**: Anthropic은 더 새로운 버전인 `web_search_20260209`와 `web_search_20260318`도 제공합니다. Anthropic에 따르면 이 버전들은 "동적 필터링"(Claude가 읽기 전에 코드가 먼저 검색 결과를 필터링하는 기능)을 추가합니다. LMU AI에서는 테스트 시 두 버전 모두 정상적으로 응답했지만, 응답에 동적 필터링(코드 실행) 관련 내용이 없었고 모든 검색 블록의 `caller`가 `{"type": "direct"}`였습니다. 즉 `web_search_20250305`와 동일하게 동작했습니다. **`web_search_20250305` 사용을 권장합니다.**

## 4. 응답 구조 [#response]

웹 검색 응답의 `content`에는 다음 블록이 순서대로 포함됩니다. Claude가 여러 번 검색하면 처음 두 종류의 블록이 반복됩니다:

| 블록 / 필드 | 설명 |
|---|---|
| `server_tool_use` | Claude가 시작한 한 번의 검색. `input.query`는 실제로 사용된 검색어입니다 |
| `web_search_tool_result` | 해당 검색의 결과. `tool_use_id`는 위 블록의 `id`와 일치합니다. 일반적으로 `content`는 결과 목록입니다 |
| `web_search_tool_result.content[]` | 각 결과에는 `title`, `url`, `page_age`(페이지 날짜, `null`일 수 있음), `encrypted_content`(암호화된 페이지 내용으로, 멀티턴 대화에서는 변경 없이 그대로 다시 보내야 함)가 있습니다 |
| `text` | 답변. 여러 개의 `text` 블록으로 나뉘며, 인용이 있는 구간에는 `citations`가 포함됩니다 |
| `text.citations[]` | `web_search_result_location` 타입의 문장 단위 인용. `url`과 `title`은 해당 구간의 출처, `cited_text`는 인용된 텍스트이며, `encrypted_index`는 멀티턴 대화에서 변경 없이 그대로 다시 보내야 합니다 |
| `stop_reason` | 응답이 정상적으로 끝나면 `end_turn` |
| `usage.server_tool_use.web_search_requests` | 이 요청의 검색 횟수. **일부 응답에는 이 필드가 없습니다.** 실제 검색 횟수는 `server_tool_use` 블록 수를 세어 확인하세요 |

<Callout type="info" title="HTTP 200이라고 모든 검색이 성공한 것은 아닙니다">

검색이 실패해도 HTTP 상태는 200이며, 오류는 해당 `web_search_tool_result`에 담깁니다. 8절을 참고하세요.

</Callout>

`claude-opus-5-5`처럼 먼저 사고하는 모델에서는 응답에 `thinking` 블록도 포함됩니다. `max_tokens`를 충분히 크게(예: `8000`) 설정하세요. 그렇지 않으면 사고 도중 응답이 잘려 답변 텍스트를 받지 못할 수 있습니다.

## 5. Python 예제: 검색어, 출처, 인용 읽기 [#python]

먼저 공식 Anthropic SDK를 설치합니다:

```bash
pip install anthropic
```

```python
import os

import anthropic

client = anthropic.Anthropic(
    base_url="https://api.lmuai.com",
    api_key=os.environ["LMU_API_KEY"],
)

response = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=4096,
    messages=[{"role": "user", "content": "What's the weather in Beijing today? Search the web and cite your sources."}],
    tools=[{"type": "web_search_20250305", "name": "web_search", "max_uses": 3}],
)

for block in response.content:
    if block.type == "server_tool_use":
        print("Search query:", block.input["query"])
    elif block.type == "web_search_tool_result":
        if isinstance(block.content, list):
            for r in block.content:
                print("  Result:", r.title, r.url)
        else:
            print("  Search error:", block.content.error_code)
    elif block.type == "text":
        print("Answer:", block.text)
        for c in block.citations or []:
            print("    Citation:", c.title, c.url, "|", c.cited_text[:40])

print("stop_reason:", response.stop_reason)
print("Searches:", sum(b.type == "server_tool_use" for b in response.content))
```

<Callout type="warn" title="먼저 Claude Code 환경 변수를 해제하세요">

환경에 `ANTHROPIC_AUTH_TOKEN` 또는 `ANTHROPIC_BASE_URL`이 설정되어 있으면(예: 이 컴퓨터에 Claude Code가 설정된 경우) SDK가 이를 자동으로 읽어 추가 인증 헤더를 보내거나 요청을 다른 곳으로 보냅니다. 코드에서 `api_key`를 전달해도 `401 INVALID_API_KEY`가 발생할 수 있습니다. 먼저 다음을 실행하세요:

```bash
unset ANTHROPIC_AUTH_TOKEN ANTHROPIC_BASE_URL
```

</Callout>

## 6. 스트리밍 [#streaming]

요청 본문에 `"stream": true`를 추가하고 나머지는 그대로 둡니다. 이벤트는 다음 순서로 도착합니다:

1. `message_start`.
2. `server_tool_use` 블록의 `content_block_start`, 이어서 검색어를 스트리밍하는 `input_json_delta` 이벤트.
3. 서버가 검색을 실행합니다. 이 동안에는 새 콘텐츠 블록이 도착하지 않습니다.
4. `web_search_tool_result` 블록의 `content_block_start`. 전체 결과 목록이 한 번에 전달됩니다.
5. Claude가 여러 번 검색하면 2–4단계가 반복됩니다.
6. 답변: `text` 블록이 `text_delta` 이벤트로 텍스트를 스트리밍하며, 인용이 있는 구간에는 인용을 하나씩 추가하는 `citations_delta` 이벤트도 전달됩니다.
7. 마지막으로 `message_delta`(`stop_reason`과 `usage` 포함)와 `message_stop`.

<Callout type="info" title="스트림 중간에 눈에 띄는 멈춤이 있을 수 있습니다">

검색을 2번 수행한 스트리밍 요청 테스트에서, 첫 이벤트는 요청 전송 후 약 16초 뒤에 도착했고, 각 검색은 검색어부터 결과까지 약 2초가 걸렸으며, 마지막 검색 결과와 답변 시작 사이에 약 7초의 멈춤이 또 있었습니다. 전체 요청에는 약 27초가 걸렸습니다. 클라이언트의 읽기 타임아웃을 충분히 길게(예: 300초) 설정하고, 멈춤을 연결 끊김으로 처리하지 마세요.

</Callout>

## 7. 멀티턴 대화 [#multi-turn]

후속 질문을 하려면 이전 응답의 `content`를 **변경 없이 그대로** `assistant` 메시지로 다시 보낸 다음 새 `user` 메시지를 추가합니다. 여기에는 `server_tool_use`, `web_search_tool_result`, 인용이 포함된 `text` 블록이 모두 들어갑니다. 텍스트만 남기지 말고, `encrypted_content`나 `encrypted_index`를 수정하지 마세요.

아래 예제는 첫 번째 턴에서 출력을 스트리밍하고, 두 번째 턴에서 이전 내용을 다시 보내 후속 질문을 합니다. LMU AI에서 테스트되었습니다:

```python
import os

import anthropic

client = anthropic.Anthropic(
    base_url="https://api.lmuai.com",
    api_key=os.environ["LMU_API_KEY"],
)
tools = [{"type": "web_search_20250305", "name": "web_search", "max_uses": 3}]

# Turn 1: streaming
question = "What is the most recent Claude model Anthropic has released? Search the web and cite your sources."
with client.messages.stream(
    model="claude-sonnet-5-5",
    max_tokens=4096,
    messages=[{"role": "user", "content": question}],
    tools=tools,
) as stream:
    for text in stream.text_stream:
        print(text, end="", flush=True)
    message = stream.get_final_message()

print("\n\nTurn 1 block types:", [b.type for b in message.content])
print("Turn 1 citations:", sum(len(b.citations or []) for b in message.content if b.type == "text"))

# Turn 2: send the previous content back unchanged
messages = [
    {"role": "user", "content": question},
    {"role": "assistant", "content": message.content},
    {"role": "user", "content": "How large is its context window?"},
]
followup = client.messages.create(
    model="claude-sonnet-5-5",
    max_tokens=4096,
    messages=messages,
    tools=tools,
)
print("Turn 2 stop_reason:", followup.stop_reason)
print("Turn 2 block types:", [b.type for b in followup.content])
print("Turn 2 answer:", "".join(b.text for b in followup.content if b.type == "text")[:300])
```

`stream.get_final_message()`가 반환하는 전체 응답은 4절과 구조가 같으며, 다음 턴에 그대로 다시 보낼 수 있습니다.

**`stop_reason`이 `pause_turn`인 경우**: Anthropic에 따르면 서버 측 검색 루프가 너무 오래 실행되면 서버가 이를 일시 중지하고 `pause_turn`을 반환합니다. 해당 응답의 `content`를 변경 없이 `assistant` 메시지로 다시 보내고 같은 요청을 다시 보내면 이어서 진행됩니다. "계속" 같은 추가 user 메시지는 넣지 마세요. LMU AI에서는 검색을 12번 수행한 요청 테스트도 `end_turn`으로 정상 종료되었으며, `pause_turn`은 발생하지 않았습니다.

## 8. 검색 오류 [#errors]

검색이 실패해도 HTTP 상태는 **여전히 200**이며, 해당 `web_search_tool_result.content`는 결과 목록 대신 오류 객체가 됩니다:

```json
{
  "type": "web_search_tool_result",
  "tool_use_id": "srvtoolu_...",
  "content": {"type": "web_search_tool_result_error", "error_code": "max_uses_exceeded"}
}
```

가능한 `error_code` 값(Anthropic 문서 기준이며, LMU AI 테스트에서는 `max_uses_exceeded`가 확인되었습니다):

| `error_code` | 의미 |
|---|---|
| `max_uses_exceeded` | 검색 횟수가 `max_uses`를 초과했습니다 |
| `too_many_requests` | 검색이 속도 제한에 걸렸습니다. 잠시 후 다시 시도하세요 |
| `invalid_tool_input` | 검색 파라미터가 잘못되었습니다 |
| `query_too_long` | 검색어가 너무 깁니다 |
| `request_too_large` | 요청이 너무 큽니다. 보통 도메인 목록이 너무 길 때 발생합니다 |
| `unavailable` | 검색 서비스 내부 오류입니다. 잠시 후 다시 시도하세요 |

검색은 실행되었지만 결과가 없으면 `content`는 오류가 아니라 빈 목록 `[]`입니다.

## 9. OpenAI 프로토콜로 호출하기 [#openai-protocol]

Claude 모델은 [OpenAI 프로토콜](/ko/docs/guide/api-protocols)로도 호출할 수 있습니다. `tools`에 `{"type": "web_search"}`를 넣으면 모델이 웹을 검색하며, 답변 품질에도 문제가 없습니다:

| 프로토콜 | 엔드포인트 | 검색 도구 | 웹 검색 | 구조화된 인용 |
|---|---|---|---|---|
| Anthropic Messages | `/v1/messages` | `{"type": "web_search_20250305", "name": "web_search"}` | ✅ | ✅ `citations` |
| OpenAI Chat Completions | `/v1/chat/completions` | `{"type": "web_search"}` | ✅ | ❌ `annotations` 없음, 링크는 본문에만 표시 |
| OpenAI Responses | `/v1/responses` | `{"type": "web_search"}` | ✅ | ❌ `annotations`가 비어 있음, 링크는 본문에만 표시 |

**출처 목록이나 문장 단위 인용이 필요하면 Anthropic Messages 프로토콜(`/v1/messages`)을 사용하세요.**

## 10. 비용 [#billing]

웹 검색 요청은 사용한 모델 기준으로 과금되며, 각 요청의 비용은 콘솔의 "사용량" 페이지에서 확인할 수 있습니다. 검색 결과는 입력 Token으로 계산됩니다. 이 페이지의 예제 요청은 두 번 검색하여 약 34,000개의 입력 Token을 사용했으며, 이는 검색 없는 일반 요청보다 훨씬 많습니다. 한 요청에서 여러 번 검색할 수 있으므로 `max_uses`로 검색 횟수를 제한해 비용을 관리할 수 있습니다.

## 11. 문제 해결 [#troubleshooting]

| 증상 | 원인 | 해결 방법 |
|---|---|---|
| 응답이 `Search results for "..."`로 시작하는 결과 목록이며, 답변과 `citations`가 없음 | 사용 중인 그룹이 아직 완전한 웹 검색을 지원하지 않음 | **Claude-MAX-高倍率分组（不限制）** 그룹의 키를 사용하세요 |
| 응답에 `server_tool_use`가 없음 | Claude가 검색이 필요 없다고 판단함 | "웹을 검색하고 출처를 인용해 줘"처럼 프롬프트에서 명시적으로 요청하세요 |
| `web_search_tool_result`의 결과가 빈 목록 `[]` | 일치하는 결과가 없거나, `allowed_domains`와 `blocked_domains`를 함께 보냄 | 도메인 제한을 완화하고 두 목록 중 하나만 남기세요 |
| `Upstream access forbidden` 메시지와 함께 `502` | `User-Agent` 헤더가 Python 표준 `urllib` 라이브러리의 기본값인 `Python-urllib/3.x`여서 업스트림이 차단함 | 공식 SDK나 `requests` 같은 일반 라이브러리를 사용하거나 다른 `User-Agent`를 설정하세요 |
| curl은 되는데 SDK에서 `401 INVALID_API_KEY` 반환 | SDK가 `ANTHROPIC_AUTH_TOKEN` 환경 변수를 자동으로 읽음 | 먼저 `unset ANTHROPIC_AUTH_TOKEN ANTHROPIC_BASE_URL`을 실행하세요 |
| `thinking` 블록은 있는데 답변이 없고 `stop_reason`이 `max_tokens` | 사고 과정이 `max_tokens`를 모두 사용함 | `max_tokens`를 늘리세요. `claude-opus-5-5`에는 `8000` 이상을 권장합니다 |
| `usage`에 `server_tool_use`가 없음 | 일부 응답은 검색 횟수를 반환하지 않음 | 대신 `server_tool_use` 블록 수를 세세요 |

프로토콜에 대한 자세한 내용은 [API 프로토콜](/ko/docs/guide/api-protocols)을, 일반적인 오류는 [오류 코드](/ko/docs/guide/errors)를 참고하세요. Anthropic 공식 문서는 [웹 검색 도구](https://platform.claude.com/docs/en/agents-and-tools/tool-use/web-search-tool)를 참고하세요.
