## Проблема 1: Разрыв потока / тайм-аут [#issue-1]

**Сообщение об ошибке:**
```
stream disconnected before completion: error sending request for url
(https://api.lmuai.com/responses)
```

**Причина:** классический разрыв потока, обычно из-за:
- нестабильной локальной сети (частое переключение Wi-Fi / мобильной связи, слабый сигнал, потеря пакетов)
- **включён VPN / прокси / системный прокси**: прокси меняет выходной IP и разрывает соединение

**Решение:**
<CN>
1. **Отключите любой VPN / прокси / системный прокси и повторите попытку** — LMU AI — это прямое внутреннее соединение, VPN не нужен
2. Убедитесь, что ваша локальная сеть стабильна; при необходимости переключитесь на более надёжную сеть
</CN>
<Intl>
1. **Отключите любой VPN / прокси / системный прокси и повторите попытку** — зарубежный шлюз LMU AI подключается напрямую, дополнительный прокси не нужен
2. Убедитесь, что ваша локальная сеть стабильна; при необходимости переключитесь на более надёжную сеть
</Intl>

<CN>
<Callout type="info" title="VPN не нужен — прямой доступ внутри Китая самый быстрый">

Шлюз LMU AI размещён **внутри материкового Китая**, поэтому к нему можно обращаться напрямую из внутренней сети **без VPN, прокси или обходных путей**. Прямое соединение даёт самые быстрые и стабильные результаты; напротив, VPN или прокси, который меняет выходной IP, склонен вызывать разрывы потока.

</Callout>
</CN>
<Intl>
<Callout type="info" title="Прямой зарубежный доступ — дополнительный прокси не нужен">

К **международному шлюзу** LMU AI `api.lmuai.com` можно обращаться напрямую из сетей за пределами материкового Китая **без дополнительного прокси**. Прямое соединение даёт самые быстрые и стабильные результаты; напротив, прокси, который меняет выходной IP, склонен вызывать разрывы потока.

</Callout>

## Проблема 2: Ошибка повтора 429 [#issue-2]

**Сообщение об ошибке:**
```
exceeded retry limit, last status: 429 Too Many Requests
```

**Причина:** ваша дневная квота исчерпана.

**Решение:**
1. Откройте **Моя подписка** и подтвердите, исчерпана ли дневная квота
2. Если вам нужно больше, купите тариф **другого уровня**, затем переключитесь на группу нового тарифа в разделе **API-ключи** в консоли

<Callout type="warn" title="Продление против добавления квоты">

- **Не покупайте тот же тариф** — тот же тариф продлевается, но не добавляет квоту
- Чтобы добавить квоту, купите другой тариф (например, смените дневной абонемент на месячный)

</Callout>

## Проблема 3: 401 Incorrect API key [#issue-3]

**Сообщение об ошибке:**
```
unexpected status 401 Unauthorized: Incorrect API key provided
```

**Причина:** запрос всё ещё пошёл на официальную конечную точку OpenAI, а не на наш relay.

**Решение:**
1. Убедитесь, что оба файла `config.toml` и `auth.json` были созданы или заменены правильно
2. Перезапустите IDE (VS Code / Cursor и т. п.), чтобы перезагрузить файлы конфигурации
3. Если вы ранее входили с официальной учётной записью или учётной записью другого провайдера, сначала выйдите, затем настройте заново

<Callout type="info" title="Что делать при возникновении ошибки">

Сделайте скриншот ошибки и переведите его — это обычно быстро указывает на причину.

</Callout>

## Проблема 4: Scripts are disabled (Windows) [#issue-4]

**Сообщение об ошибке:**
```
codex: cannot be loaded because running scripts is disabled on this system.
```

**Решение:** выполните следующее в терминале, затем откройте новый терминал:

```powershell
Set-ExecutionPolicy RemoteSigned -Scope CurrentUser
```

## Проблема 6: 503 No available accounts (переменные окружения переопределяют ключ) [#issue-6]

**Сообщение об ошибке:**
```
Error code: 503 - {'error': {'message': 'No available accounts: no available accounts', 'type': 'api_error'}}
```

**Причина:** ваш `~/.zshrc` (или `~/.bashrc`) задаёт `ANTHROPIC_AUTH_TOKEN` / `ANTHROPIC_BASE_URL` / `ANTHROPIC_MODEL`. После запуска оболочки эти переменные вступают в силу глобально и переопределяют API-ключ, настроенный в вашем IDE (Cursor, VS Code и т. п.), поэтому запрос использует неправильный ключ.

**Решение (выберите одно):**

**Вариант A: удалить переменные из `.zshrc`**

Откройте `~/.zshrc` и удалите эти строки:
```bash
export ANTHROPIC_AUTH_TOKEN="..."
export ANTHROPIC_BASE_URL="..."
export ANTHROPIC_MODEL="..."
```
Затем выполните `source ~/.zshrc`, чтобы применить, и перезапустите IDE.

**Вариант B: переместить переменные в отдельный файл, загружаемый только для Claude Code CLI**

1. Создайте `~/.claude_env` с тремя строками:
```bash
export ANTHROPIC_AUTH_TOKEN="sk-your-lmu-ai-api-key"
export ANTHROPIC_BASE_URL="https://api.lmuai.com"
export ANTHROPIC_MODEL="the-model-you-use"
```

2. Удалите эти три строки из `~/.zshrc`.

3. Загружайте их вручную при запуске Claude Code:
```bash
source ~/.claude_env && claude
```

Таким образом IDE использует ключ из своего файла конфигурации, а Claude Code CLI использует переменные окружения, не мешая друг другу.

## Проблема 7: 400 Invalid signature in thinking block (переключение моделей между группами) [#issue-7]

**Сообщение об ошибке:**
```
upstream error: 400 messages.<index>.content.<index>:
Invalid `signature` in `thinking` block
```

**Причина:** когда Extended Thinking Claude генерирует блок `thinking`, он прикрепляет **зашифрованную подпись**, которая тесно связана с **конкретной вышестоящей учётной записью**, которая её создала. Если вы **переключаете модели между группами** в рамках одного разговора (например, с `claude-sonnet-5` в группе «Claude-Pro прямой» на `claude-fable-5` в группе «Claude-MAX с высоким множителем»), клиент отправляет предыдущую историю (включая подписанный блок thinking) вышестоящей учётной записи новой группы. Разные группы используют **разные вышестоящие серверы** и не могут проверить подпись, выданную другим, поэтому возвращается 400.

**Типичные триггеры:**
- Клиент поддерживает переключение моделей в середине разговора и переносит всю предыдущую историю
- Группы до и после переключения относятся к **разным вышестоящим учётным записям** (например, «прямая группа» ↔ «relay / группа MAX с высоким множителем»)

**Решение (любое одно):**

1. **Начните новый разговор при переключении групп** — отсутствие старой истории — самое простое и надёжное решение.
2. **Используйте одну группу на разговор** — если вам нужна совместная работа нескольких моделей, переключайтесь внутри одной группы (один вышестоящий сервер).
3. **Удалите блоки thinking из истории** — если клиент поддерживает редактирование истории, удалите блоки `thinking` перед переключением групп.

<Callout type="info" title="Почему повторная попытка не помогает?">

Это **невосстановимая клиентская ошибка 4xx, вызванная недопустимой подписью**. Как только шлюз обнаруживает её, он передаёт 400 напрямую обратно клиенту и не повторяет автоматически на другой учётной записи — потому что любой несоответствующий вышестоящий сервер завершится той же ошибкой.

</Callout>

## Проблема 8: 400 Unknown parameter: 'tools[0].n' (tools отправлены на конечную точку изображений) [#issue-8]

**Сообщение об ошибке:**
```
400 - {'error': {'code': 'unknown_parameter', 'message': "Unknown parameter: 'tools[0].n'.", 'param': 'tools[0].n', 'type': 'invalid_request_error'}}
```

**Затронутые конечные точки:** `/v1/images/generations`, `/v1/images/edits` (генерация / редактирование изображений).

**Причина:** клиент поместил массив `tools` в тело запроса изображения, с полем `n` внутри `tools[0]`. Конечные точки изображений OpenAI **не принимают `tools`** (вызовы инструментов относятся к конечным точкам Chat / Responses; у конечных точек изображений нет такого понятия), поэтому вышестоящий сервер отклоняет запрос с 400.

Обычно это исходит от клиента / обёртки SDK с ошибкой, который помещает «количество изображений `n`» в неправильное место — вложенным в `tools[0].n` или скопированным из шаблона запроса Chat.

**Решение:**

1. **Удалите поле `tools` из тела запроса** — `generations` / `edits` изображений не поддерживают вызовы инструментов; уберите поле полностью.
2. **Чтобы сгенерировать несколько изображений, укажите количество в верхнеуровневом `n`** — только `/v1/images/generations` поддерживает `n` (несколько за вызов); `/v1/images/edits` — нет, поэтому уберите `n` там.
3. **Проверьте версию клиентского SDK** — если обёртка строит параметры автоматически, обновите или замените её, чтобы она не применяла шаблон Chat к конечным точкам изображений.

<Callout type="info" title="Почему смена учётных записей / повторная попытка не помогают?">

Это клиентская ошибка 4xx, вызванная **недопустимым телом запроса**, не связанная с вышестоящей учётной записью или группой — шлюз передаёт запрос как есть, и любая учётная запись вернёт ту же ошибку 400. Вы должны исправить параметры запроса, которые отправляет клиент.

</Callout>

## Проблема 10: 401 API_KEY_REQUIRED (Codex не отправляет ключ) [#issue-10]

**Сообщение об ошибке:**
```
unexpected status 401 Unauthorized: {"code":"API_KEY_REQUIRED","message":"API key is required in Authorization header (Bearer scheme), x-api-key header, or x-goog-api-key header"}, url: https://api.lmuai.com/responses, request id: ...
```

**Причина:** ошибка Codex — когда пользовательский провайдер модели использует `wire_api = "responses"`, запрос, который отправляет Codex, **вообще не несёт API-ключ** (ни `Authorization`, ни `x-api-key`, ни `x-goog-api-key` не отправляется), поэтому шлюз не находит ключ и возвращает 401 `API_KEY_REQUIRED`.

Обратите внимание, это отличается от `Incorrect API key provided` в [Проблема 3](#issue-3): там отправляется ключ, который неверен (обычно потому, что запрос пошёл на официальную конечную точку OpenAI вместо relay LMU AI), тогда как здесь **не отправляется никакого ключа вообще**.

**Решение:** откройте `~/.codex/config.toml`, найдите раздел вашего провайдера модели `[model_providers.<ID>]` (обычно `[model_providers.codex]`, если вы следовали руководству этого сайта) и добавьте `requires_openai_auth = true` внутри него:

```toml
[model_providers.codex]
name = "codex"
base_url = "https://api.lmuai.com"
wire_api = "responses"
requires_openai_auth = true
```

Сохраните, перезапустите терминал и перезапустите Codex.

<Callout type="info" title="Пользователи, следовавшие руководству этого сайта, не затронуты">

Каждое руководство по Codex на этом сайте ([Mac](/ru/docs/tools/codex-cli-mac) / [Windows](/ru/docs/tools/codex-cli-windows) / [Server](/ru/docs/tools/codex-cli-server) / [Codex App](/ru/docs/tools/codex-app)) уже включает `requires_openai_auth = true` в своём примере `config.toml`. Если вы столкнулись с этой ошибкой, ваша конфигурация, вероятно, была скопирована из более старого руководства или другого источника, который опустил эту строку — добавьте её, как показано выше.

</Callout>
