تشرح هذه الصفحة المبادئ التي تتبعها LMU AI عند التعامل مع بيانات المستخدمين. نحن نعتبر "الحد الأدنى من التخزين، والعزل، والشفافية" الأسس الثلاثة لمعالجتنا للبيانات.

## ما البيانات التي نعالجها

نقسم البيانات إلى فئتين: **بيانات الحساب** و**بيانات الطلب**. تتم معالجة الفئتين وتخزينهما بطرق مختلفة تمامًا.

### بيانات الحساب

| النوع | المحتوى | الغرض |
|------|------|------|
| معلومات الهوية | البريد الإلكتروني، رقم الهاتف | تسجيل الدخول، استعادة كلمة المرور، الإشعارات |
| معلومات الفوترة | الخطة، الحصة، سجلات الطلبات | الفوترة والفواتير |
| معلومات بيانات الاعتماد | مفتاح API (مخزَّن مشفَّرًا)، جلسة تسجيل الدخول | المصادقة |
| بيانات وصف الاستخدام | وقت الاستدعاء، النموذج، استخدام Token، المدة | الفوترة، الإحصائيات، التقارير |

### بيانات الطلب

| النوع | المحتوى | الغرض |
|------|------|------|
| نص الطلب | الموجه والرسائل والمعاملات التي ترسلها | يُعاد توجيهها إلى النموذج الأعلى لإنشاء استجابة |
| نص الاستجابة | المحتوى الذي يعيده النموذج | يُعاد إليك |

**التمييز الرئيسي**: تُستخدم بيانات الحساب لتشغيل المنصة نفسها؛ بينما تُستخدم بيانات الطلب فقط لإكمال استدعاء API الحالي والفردي.

## أين تُخزَّن البيانات

تتكون بنيتنا التحتية من طبقتين:

**طبقة الوصول (داخل الصين)**
- الخوادم الرئيسية، قاعدة بيانات المستخدمين، نظام الفوترة
- **تُخزَّن جميع بيانات الحساب هنا**
- بريدك الإلكتروني ورقم هاتفك وطلباتك ومفتاح API لا تغادر الصين أبدًا

**طبقة القنوات الأعلى (متعددة المناطق، بما في ذلك الخارج)**
- تُستخدم للوصول إلى الواجهات الرسمية لمزوّدي النماذج مثل OpenAI / Anthropic / إلخ
- تعمل هذه القنوات **فقط كمُرحِّل لحركة مرور النموذج** ولا تحتفظ بأي معلومات هوية للمستخدم
- لا تُخزِّن عُقد القنوات حسابات المستخدمين ولا تعرف من أي مستخدم يأتي الطلب (فهي ترى فقط حمولة الطلب المجهولة الهوية)

## سياسة الاحتفاظ بالسجلات

| نوع البيانات | مدة الاحتفاظ | موقع التخزين |
|---------|---------|---------|
| محتوى نص الطلب / الاستجابة | **لا يُحتفظ به** | — |
| بيانات وصف الاستدعاء (الوقت، النموذج، Token، المدة، رمز الحالة) | 90 يومًا | داخل الصين |
| سجلات الأخطاء (قد تتضمن أجزاء مقتطعة من الطلب) | 90 يومًا | داخل الصين |
| بيانات الحساب والطلبات | طوال عمر الحساب؛ تُمحى خلال 30 يومًا من الإلغاء | داخل الصين |

**حول محتوى الطلب**

- نحن **لا نُخزِّن موجهك أو محتوى استجابتك** — بمجرد إعادة توجيه الطلب، يتم تحريره من الذاكرة ولا يُكتب أبدًا في أي قاعدة بيانات أو ملف
- عندما تُعيد قناة أعلى خطأً، قد يحتوي سجل الخطأ على **أجزاء مقتطعة من الطلب** (تُستخدم لإعادة إنتاج المشكلة)؛ تُمحى هذه البيانات بعد 90 يومًا
- لا تُستخدم سجلات الأخطاء لتدريب أي نموذج ولا تتم مراجعتها بشكل استباقي من قِبل البشر؛ ولا يصل إليها سوى المهندسين المعنيين عندما تُقدّم تذكرة تحتاج إلى مساعدة في استكشاف الأخطاء

<Callout type="info" title="سجلات تدقيق اختيارية لفئة المؤسسات">

يمكن لعملاء المؤسسات الاشتراك اختياريًا في ميزة سجل التدقيق والاحتفاظ ببيانات الطلب / الاستجابة وفقًا لمتطلبات الامتثال في شركتك. بمجرد تفعيلها، تُخزَّن السجلات مشفَّرة، ويمكن التحكم في الوصول إليها من قِبل مسؤولي شركتك. راجع [خطط المؤسسات](/ar/docs/enterprise) للتفاصيل.

</Callout>

## نقل البيانات عبر الحدود

نظرًا لأن خوادم النماذج الأعلى (Claude وGPT وما إلى ذلك) تقع في الخارج، **فإن نصوص الطلب والاستجابة لاستدعاء API تمر عبر القنوات الخارجية أثناء إعادة التوجيه**. هذا مسار تقني ضروري لأي خدمة ترحيل تصل إلى واجهات API للنماذج الكبيرة الخارجية.

التزاماتنا في هذه المرحلة:

- **لا نحتفظ بأي بيانات على العُقد الخارجية**: القنوات تُعيد التوجيه فقط، وتُحرَّر الذاكرة بمجرد اكتمال إعادة التوجيه
- **لا نحمل هوية المستخدم**: الطلبات التي تراها القنوات الأعلى تكون قد جُرِّدت من حقول الحساب مثل البريد الإلكتروني ورقم الهاتف وارتباطات الطلبات
- **النقل المشفَّر**: المستخدم ↔ طبقة الوصول، وطبقة الوصول ↔ القناة الأعلى، والقناة الأعلى ↔ مزوّد النموذج كلها بمعيار TLS 1.2+ من طرف إلى طرف
- **لا نشارك مع أطراف ثالثة**: باستثناء مزوّدي النماذج الأعلى الضروريين لإكمال الاستدعاء الحالي، لا نمرر محتوى طلبك إلى أي طرف ثالث

<Callout type="warn" title="نصيحة بشأن البيانات الحساسة">

نظرًا لأن محتوى الطلب يجب أن يمر عبر القنوات الخارجية للوصول إلى مزوّد النموذج، **لا ترسل عبر API طلبات تحتوي على بيانات شديدة الحساسية مثل أسرار الدولة أو الأسرار التجارية أو أرقام الهوية الشخصية**. إذا كانت لديك متطلبات امتثال من هذا النوع، فاتصل بفريق المبيعات لمناقشة النشر داخل المؤسسة أو قناة متوافقة.

</Callout>

## ما الذي لا نفعله

- **لا نقرأ** موجهك أو محتوى استجابتك لأغراض التحليل البشري أو التحليل التجاري أو أي تدريب للنماذج
- **لا نبيع** أيًا من بياناتك لأطراف ثالثة
- **لا نحتفظ** بمحتوى الطلب والاستجابة **دون إبلاغك**
- **لا ننقل بيانات الحساب عبر الحدود** (تُخزَّن بيانات الحساب داخل الصين فقط)

## ممارسات الأمان

- تُخزَّن مفاتيح API مشفَّرة في قاعدة البيانات، مع إظهار عدد قليل فقط من الأحرف الأمامية والخلفية
- تُسجَّل جميع العمليات الداخلية التي تصل إلى قاعدة البيانات في سجلات التدقيق
- تؤدي التغييرات على المفاتيح (الخطة، إعادة تعيين مفتاح API، عمليات السحب، إلخ) إلى إشعارات بريد إلكتروني / رسائل نصية
- يجب أن يمر أعضاء الفريق الذين يصلون إلى بيانات الإنتاج عبر الموافقة ومبدأ الحد الأدنى من الامتيازات

إذا لاحظت وجود اشتباه في خلل بحسابك، فيرجى فورًا:
1. إعادة تعيين مفتاح API في وحدة التحكم
2. الاتصال بالمبيعات أو الدعم: business@lmuai.com / WeChat 18599001010

## دعم امتثال المؤسسات

يجب على عملاء المؤسسات الذين لديهم أي من الاحتياجات التالية التواصل عبر قناة الأعمال:

- توقيع اتفاقية معالجة البيانات (DPA)
- سياسات احتفاظ مخصصة بالسجلات
- نشر بوابة داخل المؤسسة (لا يمر محتوى الطلب عبر القنوات المشتركة)
- مواد داعمة لاستبيانات MLPS / GDPR / SOC2

## تغييرات السياسة

إذا كانت هناك تغييرات جوهرية على هذه السياسة، فسننشر إشعارًا في مكان بارز على الموقع ونُخطر المستخدمين النشطين عبر البريد الإلكتروني. يشكّل استمرارك في استخدام الخدمة بعد تحديث السياسة قبولًا للسياسة الجديدة.
